## 必须遵守

- Covelet UI 同时遵循 Apple HIG 与现行产品规格。用清楚的层级、熟悉且一致的控件、及时反馈和用户可控的操作组织界面，参见 [Apple HIG 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles)。
- 禁止冗长的「AI 提示味」解释：用真人产品的简短、直接、面向行动的语言，参见 [Apple HIG Writing](https://developer.apple.com/design/human-interface-guidelines/writing)。
- 视觉或文案拿不准时，停止相关实现与验收，找 Creative Director 对齐；在 PR 记录不确定点和决策链接，仅在达成一致后恢复。不得强推（force-push）或绕过验收门。
- 下列项目由 reviewer 逐项勾选。不适用必须在 PR 说明具体项目及理由；未完成、未验证不能算通过。

## Reviewer 检查

- [ ] **规格与 HIG**：改动符合适用产品规格；PR 说明相关 HIG 原则及其在实际改动区域的落实方式。
- [ ] **密度、层级、间距**：主次与主要操作一眼可辨；信息不过载，分组、对齐和留白帮助阅读。
- [ ] **视觉一致且克制**：颜色、字号、图标、圆角与控件沿用现有约定；装饰不抢过内容和操作。
- [ ] **真人语气**：文案简短、具体，无冗长铺垫、空泛承诺或重复解释；按钮直接说明动作与结果。
- [ ] **状态与反馈**：空态、加载、错误均可理解，下一步明确（如添加、取消、重试），操作后有适当反馈。
- [ ] **设置**：名称与说明易懂，默认值、当前状态和生效结果清楚；用户知道如何选择或撤回操作。
- [ ] **响应式与主题**：检查受影响的窗口尺寸及浅色／深色主题，内容可读、操作可达，无挤压、遮挡或截断关键信息。
- [ ] **无障碍**：检查键盘操作、可见焦点、控件名称与状态、对比度；不只靠颜色传达信息。
- [ ] **隐私、同步与备份**：声明符合规格和实际能力；区分本机存储、可选同步与导出备份，不夸大安全或可用性。
- [ ] **关键边界**：涉及相关文案时，准确保留同步默认关闭、浏览器原生同步停用、JSON/ZIP 非加密备份等事实；不把 Beta 或未验收能力写成已验证。
- [ ] **证据与对齐**：受影响状态、尺寸、主题有适用截图和实际检查结果；未验证边界明确，Creative Director 待决项已对齐。
