# Covelet 0.5.0 功能范围

0.5.0 规划 12 项新功能，解决收藏之后的查找、整理、再使用和恢复。一个具体场景是：用户保存一篇技术文章，写下「解决登录回调问题」，标上「开发」标签；遇到问题时可以搜这句备注，平时从保存的「开发未读」清单继续阅读；重要段落可以连同出处存成便笺。积累的链接可以用列表整理，误删后可以恢复，换设备可以用密码保护的备份带走。

规划日期为 2026 年 11 月 11 日。应用基线为已发布的 `v0.4.0`，首批 `feature/0.4.2` 从包含它的 `main` 提交 `fda3ad5` 起步。后续分支逐批从上一批自测通过并合入后的 `main` 创建。本轮交付功能范围与分支计划，功能实现另行开展。 [0.4.0 发布](https://github.com/MorleyZhou/Covelet/releases/tag/v0.4.0) · [上一批功能范围](0.4.0%20功能范围.md)

## 现有能力与选择依据

0.4.0 已有桌面命名、排序和默认桌面，文件夹批量打开，快捷键唤起搜索，搜索类型与桌面范围筛选，工具栏收藏到指定位置，稍后读加入桌面，布局批量移动或复制，首次引导，Markdown 链接导入和书签 HTML 导出。便笺富文本编辑、逐条阅读状态、工具回收站和完整明文备份也已存在。下列 12 项按新的用户动作计数，共享的数据升级、翻译和测试属于交付工作。

## 12 项功能与验收

| 编号 | 功能 | 用户能完成的新动作 | 首版验收 |
| --- | --- | --- | --- |
| 01 | 链接备注 | 给网站或稍后读写一句「为什么收藏」，以后按这句话找回。 | 纯文本备注可在保存和编辑时填写，可搜索并显示命中摘要。导航移动、复制、阅读项转桌面时按明确规则保留备注；完整备份和同步保留。 |
| 02 | 跨内容标签 | 给网站、便笺和稍后读共用「开发」「项目 A」等标签，点击多个标签交叉查找。 | 统一的扁平标签支持添加、移除和改名。多选标签表示同时包含，当前条件清晰可见。改名不丢关联，标签及结果数量遵循内容隐藏规则。 |
| 03 | 保存筛选为动态清单 | 保存「稍后读＋开发标签＋未读」为「开发未读」，下次一键打开，新收藏自动进入。 | 保存查询文字、类型、标签及适用的范围、域名或阅读状态。重开时实时计算结果，支持改名、更新条件、独立隐藏和删除清单。删除清单保留原内容。 |
| 04 | 链接列表整理 | 在一个列表中查看各桌面和文件夹的网站，按名称、位置或域名查找并整理。 | 网站和文件夹显示真实归属，支持列表排序、备注编辑和多选标签处理。移动、复制复用 0.4 的操作。切换列表排序不改变桌面布局。 |
| 05 | 已存链接重复审阅 | 对已经放进 Covelet 的链接检查重复，比较位置、备注和标签后选择保留项。 | 本机计算规范化后完全相同的网址，保留协议、查询参数和片段语义。同位置与跨位置副本分开展示，默认不勾选删除。合并信息先预览，被删除的副本进入导航回收站。 |
| 06 | 网页选文存为便笺 | 在网页选中一段内容，从扩展按钮保存为带页面标题和来源链接的便笺。 | 显式触发后读取选中文字，保存前可预览和修改，取消不落盘。生成普通便笺，可被现有搜索找到。空选区、受限页面和取不到的框架选区提供手工填写路径。 |
| 07 | 稍后读再看日期 | 给某篇内容设「周五再看」，到期后在稍后读的「待再看」中找到。 | 保存日期，按当前设备的本地日期判断到期。支持改期和清除日期，到期后持续保留，打开链接不自动清除日期或改阅读状态。 |
| 08 | 稍后读批量处理 | 一次选中多篇内容，标已读、标未读、归档或删除。 | 选择范围和数量明确，操作仅影响当前选中项。删除沿用工具回收站；并发修改时保留新数据并提示处理。沿用已有的三种阅读状态。 |
| 09 | 便笺 Markdown 导入导出 | 把本地 Markdown 文件作为便笺导入，将单篇或选中的多篇便笺导出为 Markdown。 | 支持标题、段落、列表、任务、引用、代码和链接等约定结构。多篇导出打包为文件。超限或不支持的复杂块明确说明，不截断或静默丢失后报告成功。 |
| 10 | 搜索引擎关键词 | 给现有引擎设 `gh`，输入 `gh react` 直接搜索 GitHub。 | 复用现有自定义引擎模板，增加唯一关键词。仅在「关键词＋空格＋非空查询」时识别，并显示目标引擎。网址直达、唯一完整桌面名跳转、普通搜索和中文输入法继续正确工作。 |
| 11 | 网站与文件夹回收站 | 删除的网站和文件夹在重启后仍可找回，可以选择恢复位置。 | 默认保留 30 天。网站、整组删除和解散文件夹分别保留正确语义，恢复含元信息及所需图标。布局草稿仅在保存后生成回收记录，取消和撤销不产生持久删除。 |
| 12 | 密码加密完整备份 | 设置一个备份密码，导出完整文件，在另一浏览器配置中输入密码恢复。 | 独立于设备密钥和同步密码，采用可移植的认证加密文件。内容和本地图片一并覆盖；错密码、损坏、超限均在业务写入前失败。继续支持旧明文备份，恢复前保留副本。 |

## 首版边界

标签、动态清单和列表共用现有数据与筛选逻辑。标签引用稳定身份，动态清单保存规则，列表展示现有导航。它们分别解决分类、重复查找和集中整理，不另外建立一份内容副本。桌面范围只适用于导航，阅读状态只适用于稍后读。保存的目标被删除时显示条件失效，不自动扩大到全部内容。

备注按具体记录保存。同一网址在不同桌面可以有不同说明，阅读项加入桌面时复制其备注和标签，之后各自编辑。复制私密内容继续继承原有标记；锁定时不通过标签建议、结果计数、清单名或重复分组透露内容。动态清单支持独立隐藏，锁定时隐藏其名称、条件和计数；普通清单只基于可见内容计算，条件引用当前不可见的目标或标签时，整条清单暂不显示。公开交换文件沿用隐藏内容排除规则，完整备份沿用其明确的私密内容处理方式。

网页摘录沿用已有 `activeTab` 和 `scripting`，由工具栏入口触发。只捕获这次选中的文字、页面标题和 URL，首版不保存全文、截图或网页副本。浏览器内部页和部分跨域框架无法读取。 [Chrome 当前标签授权](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

Markdown 便笺导入与 0.4 的「从 Markdown 提取网站链接」分别命名。导入先预览，远程图片保留为文字链接，读取本地文件不发出图片请求。复杂 Folio 块及图片的原样迁移由完整备份承担。多篇导出排除标记隐藏的便笺，单篇导出遵循同一规则。

导航回收站覆盖真正的导航删除。解散文件夹时网站仍然存在，恢复的是文件夹与可确认的成员关系；布局整组删除恢复文件夹和子项。若成员已被移动、原桌面已删除或 ID 冲突，先展示将恢复的位置和成员，保留当前记录。未过期回收内容引用的图片保留到回收期限结束；回收数据和过期删除的同步规则一并设计。

加密备份只在内存中解密和校验，通过后沿用现有恢复事务。导出文件格式、密码派生参数、内存和体积上限在 `feature/0.4.12` 实现前冻结。设备密钥、会话凭据等继续遵循现有完整备份排除规则；备份密码不持久保存，丢失后无法恢复。

## 分支和开发顺序

按六个偶数补丁号分支顺序开发，每批只放入相互关联的少量功能。每批完成开发和自测，通过后合入 `main`，再从更新后的 `main` 创建下一批分支。直接使用下表分支，不另设集成分支或额外的逐功能子分支。 [发布流程](store/release-ci.md)

每批的合并条件包括本地的该批验收、受影响旧功能回归、现有单元与浏览器测试、生产包检查，以及实际 Chrome、Edge 解压扩展验证。结果记录在该批验收记录中，未通过就留在当前分支修复。按用户新指令，后续不逐批创建 PR 或运行 GitHub Actions；本地通过后直接合入本地 `main` 并推送。各批使用隔离浏览器配置和独立远端测试目录，保留正式使用数据。

新增数据必须在所属批次一起覆盖本机加密存储、完整备份、恢复前副本和同步。`feature/0.4.2` 先确定备注与标签的可移植格式，验证旧客户端不会吞掉新字段再写回。数据格式使用独立版本标识，不用分支名称或尚未发布的包版本判断。若不能保障混合版本安全，先调整协议或制定明确的独立同步目录迁移方案，再合并。后续各批遵循同一规则，备份覆盖不能拖到最后一批才做。

`feature/0.4.4` 的动态清单先保存已经实现的条件，`feature/0.4.6` 再补日期条件及校验。`feature/0.4.12` 的加密备份负责新增密码封装和解密恢复，前面各批的新资料此前就应能通过完整备份还原。

偶数号仅用于开发分支编号。中间批次不打发布 tag、不发正式包、不提审；开发期间 package、lockfile 和 manifest 不按分支号逐批升级。六批全部合入后，在 `main` 完成跨批次验收、升级说明和发布材料，统一准备 `0.5.0` 候选包。本次授权到开发、自测和合并为止，不打发布 tag、不发布 Release、不向 Chrome 或 Edge 提审；发布与提审等待用户后续指令。

此流程下 `main` 保存自测通过的开发结果，可能包含尚未正式发布的功能。正式源码基线以发布 tag 为准，商店审核和上线状态以各商店记录为准。线上修复从当前正式 tag 创建 `feature/0.4.1`、`feature/0.4.3` 等奇数补丁分支，按需发布后将修复同步回 `main`，并回归已经合入的功能；避免把尚未提审的新功能带入修复包。正式包版本始终递增。

## 发布门槛

1. **升级和可移植性。** 用实际解压扩展验证 0.4.0 原地升级、旧 JSON/ZIP 恢复、0.5 备份在全新配置离线恢复，以及含图片和私密标记的记录。新增信息须同时覆盖本机加密存储、完整备份、自备存储同步和恢复前副本。当前同步与备份采用不同的收集规则，不能仅因同步成功就认为备份已覆盖。 [备份实现](../app/src/lib/recovery-center.js) · [同步规则](../app/src/lib/sync-data-rules.js)
2. **混合版本。** 从 0.4.2 首批就验证正式 0.4.0 与新格式的数据拒绝、冲突和重试行为，之后逐批回归。共享同步位置时，旧客户端遇到不支持的格式须安全停下，不丢字段、不静默写回缩水快照。若协议无法提供该保证，采用明确的隔离目录迁移方案，防止不兼容客户端交换写入。
3. **隐私和网络。** 锁定状态覆盖备注、标签、清单、列表、重复审阅、回收站、便笺文件交换及备份恢复。本批新增的列表、本地检索、筛选和本地 Markdown 导入不触发网络；网页选文只在显式动作下读取当前页。本批不新增必需权限或固定远端服务。
4. **可靠性。** 针对新增数据校验、筛选、关键词解析、重复判定、批量事务、回收、Markdown 转换和认证加密运行必要测试，再运行已有完整回归和包检查。覆盖取消、超限、错密码、文件篡改、未知版本、存储失败、配额不足、两标签页并发和同步冲突。失败前后比较业务数据，防止只检验错误提示。
5. **真实扩展界面。** Chrome 和 Edge 加载实际解压包，验证键盘、中文输入法、八种语言、深浅色和窄窗口。保留 0.4 的桌面跳转、默认桌面、文件夹批量打开、布局撤销、导入导出与私密内容回归。
6. **实际资料试用。** 邀请 5–8 位已有收藏的人，用各自资料完成备注查找、多标签筛选、动态清单、选文便笺、再看日期和误删恢复。一周后回访他们实际重复使用的动作，记录找不到、条件难理解和放弃的步骤，用于调整默认入口和文案。

## 后续候选

- **具体便笺或阅读项固定到桌面、桌面独立外观、操作指令面板。** 它们可以独立成批，先观察本批的搜索、清单和阅读使用情况。
- **直接导入浏览器书签。** 先核对 HTML 导入步骤是否造成明显障碍，再评估可选书签权限。现有 HTML/Markdown 链接导入继续可用。
- **Infinity 和 WeTab 专用迁移。** 取得当前版本、可再分发的脱敏样本后再确认兼容范围。 [Infinity 调研](spikes/2026-10-31-infinity-import.md) · [WeTab 调研](spikes/2026-10-31-wetab-import.md)
- **全文离线归档、失效网址联网扫描、AI 自动分类和摘要。** 分别涉及网页保存、来源授权或模型连接与数据发送，需要独立验证。窗口标签快照、浏览器阅读清单导入和已移除工具包继续遵循现有产品边界。
