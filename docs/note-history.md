# 单篇便笺历史

2026-11-24，在定时备份提交 ccd345f 之后单独实现。

## 存储选择

选择**完整快照**，不保存正文 diff。每个版本保存合法的历史便笺正文、富文本文档、标题及必要元数据；恢复只替换标题/正文/文档，保留当前便笺身份、创建时间和固定状态。完整快照允许独立预览、明确对比和不依赖中间版本的恢复，避免一个 diff 损坏影响后续版本。

独立的加密记录 `preferences/covelet.note-history.v1` 形如 `{version:1,revision,clock,notes:{noteId:[{id,n,capturedAt,record}]}}`。不用已退休的工具标签页 `snapshots`。`id` 是随机版本身份，`n` 是整个历史信封的递增 Lamport 时钟；清理后保留 clock。墙上时间只作显示，不能决定跨设备版本先后。同版本 ID 不同内容属于损坏，不能把历史正文再次字段拼接。

## 上限和清理

- 每篇最多 20 个历史版本。
- 单版最多 768 KiB（合法富文本文档自身可达 512 KiB，另有正文及元数据）。
- 每篇历史最多 4 MiB；全部历史最多 16 MiB。
- 先按每篇 `(n,id)` 清理最旧历史，再按全局 `(n,noteId,id)` 清理，直到满足全部限制。容量上限可能使某篇少于 20 版，界面说明“最多 20 版”。
- 永不以清理历史为由删除当前便笺。恢复操作新保存的当前版在该次事务中受保护，不会被刚触发的清理删掉。单版无法合法保存或写入失败时，整次恢复停止，当前内容不变。

保存真正改变标题/正文/文档的既有便笺时，在同一加密提交中先记录修改前版本，再写新便笺；新建便笺、无操作、仅固定状态/时间/本机修订变化不制造历史噪声。网页摘录追加同样经领域入口保存历史。永久删除时可清除对应历史，回收站保留期间继承当前内容的隐藏属性。

## 恢复、并发与隐私

编辑器“历史”入口针对已保存且没有未保存草稿的便笺。可只读预览、并排对比当前与所选版本，并恢复某一版。恢复校验当前便笺、历史及内容偏好修订；在现有便笺/隐私锁内，把当前版本和恢复结果一次提交。失败不覆盖另一标签页或其他设备的新修改。

历史始终继承当前便笺隐藏状态。切换便笺、隐藏/锁定或异步结果失效时清除预览；历史文本不渲染远程内容或 HTML。按照用户已确认的备份范围，完整加密备份包含隐藏便笺及其历史；访问凭据和隐藏密码仍不进入备份。

## 同步与备份兼容

历史作为便笺业务内容同步，以便笺 ID/不可变版本 ID 并集保留两端版本，并作确定性容量清理。历史修订号只用于本机 CAS，时钟和历史便笺修订不重写。合并后业务记录计数仍受现有 12,000 限制，验证不通过则保留本机。

完整备份新增 v2 的 `noteHistory`，读取器继续接受 0.6.0 的 v1 完整备份及旧 `.covelet`。外层 `.covelet` 加密格式不改；普通 JSON/ZIP 导出继续是未加密文件。恢复时只关联本次真正导入的便笺历史，追加模式跳过的同 ID 便笺不附加外来历史；覆盖当前便笺前先保存当前版。恢复前副本、原子写入及回滚包含历史，旧导航历史仍只读。

## 验证

单元测试覆盖保存、20 版/字节上限、时钟回拨、无操作不增版、恢复前保留当前版、并发/隐藏拒绝、失败原子性、双端历史合并、旧备份升级和新版完整备份往返。执行 `npm test` 和 `npm run build:unpacked`，实际浏览器编辑 A/B/C 后恢复 A 并确认 C 仍可从历史查看，再单独提交。
