# 本地 WASM 视觉增强

2026 年 10 月 21 日：原“壁纸自适应配色”和“图标视觉适配”合并为一个默认开启、可关闭的“视觉增强”，并新增导航文字及图标背景的局部自适应计算。本文描述当前源码，不表示已更新 v0.1.0 商店提交包或通过商店审核。Safari 发布暂缓。本轮已生成必要的包内 WASM 文件及校验和，按用户要求未运行测试、检查、应用构建或浏览器验收。

2026-10-21 图标修订：六个默认网站新增官网高清图片，来源与尺寸随源码记录；高清检索与图标地址属于导航能力，WASM 视觉适配仍只处理包内图片和本机资源，不偷偷读取任意远程图片。完整方形底图保留原图并铺满圆角，透明标志再调整留白，避免再次缩小带底图的素材。关闭增强不影响高清图标来源，远程图标仍可按地址显示。按用户要求，此轮未运行测试、构建或浏览器验收，旧结果不代表当前代码通过。

## 使用方式与显示边界

设置 → 增强只展示一个“视觉增强”开关，统一调整壁纸带来的界面色调、图标留白及背景、组件背景与内部配色，以及网站／文件夹／组件标题所在位置的文字明暗。顶部操作与分页也按当地背景适配。它不增加首页组件、独立工具或账号体系。

新配置默认开启；旧配置完全没有视觉字段时同样开启。旧配置没有统一字段但有原两个布尔开关时，“任一开启”迁移为开启，两者明确关闭则保持关闭；明确的新开关值优先，包括明确关闭。旧字段仍严格校验，但活动配置、ZIP 与可移植副本只保留 `settings.visualEnhancement`。旧原生同步记录继续可读，不能让默认值或旧记录重新激活用户已明确关闭的新开关。

自适应结果属于当前画面的派生值：不写回用户选择的主题、手动遮罩或图标背景色。不再为统一白字自动压暗整张壁纸，而是对各标题分别选择黑字或白字。图标处理不覆盖原始图片，不改动图标资源标识或文字图标回退。关闭时继续使用原来的手动外观与原图；初始化、解码或计算失败时同样回退，保留导航、搜索与设置操作。

图片切换、资源修改或模块关闭后，过期的异步计算结果不得重新影响当前画面。实现需要限定图片解码及计算成本，避免大图片、重复渲染或失败重试拖慢新标签页。

## 代码与数据流

WASM 二进制与 JavaScript 调用代码全部放在安装包内，随正常扩展版本提交审核。模块按需加载包内资源；不支持远程可执行文件下载、本地上传 WASM、通用代码加载器或插件市场。允许包内 WASM 的 CSP 配置不能扩大为任意脚本执行或远程脚本加载。

处理对象来自当前设备已存在的壁纸缓存和已校验的本地图标。视觉分析不增加图片上传、第三方识别服务或网址批量抓取；Bing 每日壁纸及用户逐站授权后的原有图标识别仍遵守各自已有的数据流和权限规则。

| 数据 | 保存及同步规则 |
| --- | --- |
| `settings.visualEnhancement` | 严格布尔值，默认 `true`，保留显式关闭；进入正常本地配置、ZIP 及已开启的浏览器原生／自定义同步 |
| 旧 `adaptiveWallpaper`／`adaptIcons` | 仅兼容读取并迁移；旧同步历史保留可读，新明确开关优先 |
| 手动主题、遮罩、图标背景色 | 保留原值，继续沿用既有配置规则 |
| 原始图标与壁纸 | 保留现有本地资源及缓存规则；图标原图按既有 ZIP 规则处理，壁纸不进入 ZIP 或原生同步 |
| 解码像素、色板、处理后的图像、标题颜色与计算缓存 | 属于本地派生结果，不进入可移植配置、浏览器原生同步、ZIP 或配置快照 |

两台设备可以同步启用偏好，但分别分析本机图片；图片不可用时使用原有回退，因此不承诺每台设备得到完全相同的配色或图标画面。用户仍需主动开启原生同步，启用模块不会代替其打开同步。

迁移保留已有导航、布局、手动外观和合法图片。持久存储名称、备份格式及已有 v0.1.0 发布文件保持不变。当前版本可读旧配置，不代表较旧安装版本能识别新的统一字段。

## 待后续验收的目标（本轮未执行）

- 新配置默认开启，明确关闭保留；旧开关按上述规则迁移；新旧非法布尔设置被拒绝，旧同步记录不阻止本地配置读取。
- 开启、保存、刷新、关闭以及其他设备明确关闭后，统一偏好保持一致，手动外观与原图保持可恢复。
- 切换壁纸、修改图标或连续开关时，旧计算结果不能覆盖新选择。
- WASM 初始化失败、图片不可读、透明或极端比例图片有安全回退，正常页面操作保持可用。
- 明亮、暗色、跨区域渐变与 Bing 裁切照片上的标题分别取色；窗口、布局、拖拽及分页变化后不套用旧位置结果，关闭后清除派生颜色。
- 网站列表、文件夹缩略图、文字回退和用户背景色符合各自原有规则。
- ZIP 导入导出及同步只传递统一偏好，不传递色板、像素或处理图；原始图标仍按原有 ZIP 规则验证和恢复。
- 在扩展生产包中核查 `.wasm` 为包内资源，校验 CSP 和离线回退，再在真实 Chrome／Edge 安装环境验收。普通网页预览和本地单元测试不能替代真实扩展验收。

## 当前实现

- 设置 → 增强：一个“视觉增强”开关即时保存，派生结果仅显示在当前设备。
- 共用固定 Worker 与包内 Rust 内核，在 ABI 1 增加 `analyze_caption`，原壁纸／图标操作保持兼容。本次生成的二进制为 9,471 字节，编译参数仍固定 512 KiB 内存；生成不执行验证，不代表功能验收通过。源码与编译方式见 [WASM 内核](../app/wasm/visual-core/README.md)。
- 壁纸仍用最大边 256px 的本地缩略图提取色板，同次受限解码可保留最大边 2048px 的细节图，内存最多缓存两份；不额外请求 Bing 图片。界面色调继续尊重主题，手动遮罩保留原值。
- 局部对比度：按当前壁纸的 center/cover 裁切、实际缩放、模糊、遮罩和同一层淡化渐变，直接渲染标题位置的像素块，不再下采样整幅视口。当前颜色编辑器产生的渐变与预览显式采用 sRGB，并复用同一套曲线色标；兼容识别常规旧线性渐变，其余旧 CSS 保留原背景并回退文字样式。
- 每帧最多 64 个可见文字／操作区域，各用最多 256×64、最高 2 倍设备像素采样；标题按实际字体、字距、对齐和省略号形成字形权重，包含细分坐标与分页裁切。WASM 比较黑／白字的覆盖率、低于 3:1 的严重不足、字形内八段中最弱区域和邻域明暗线条，避免亮底平均值掩盖暗线。选色参考 4.5:1，但不宣称照片上逐像素满足 WCAG；近似平局保持原色，混合背景增加小幅阴影，高风险细节再加 0.7px 反色文字描边，平整可读背景无额外效果。缩放、切屏和拖拽时刷新，静态区域复用结果。
- 图标按 alpha 边界去掉透明留白，等比居中到 128×128，内容最长边 102 像素；预乘 alpha 重采样避免透明边的颜色污染，完全透明或不可读图片回退。完整底图使用原图铺满统一圆角；X 透明圆形边缘用黑底补齐，YouTube 用原图红色补齐，Grok 的白色标志使用暗底。
- 自动配色只修改图标背景，绝不对图片使用黑白反转、染色或滤镜。另取最多 48 个可见图标位置的壁纸色调作为轻微底色：浅色透明标志用深底、深色／彩色标志用浅底；文字回退及文件夹背景按当地亮度适配。完整底图和匹配其边缘的底色保留，避免重新出现嵌套圆形／白框。用户手动背景优先，“自动”清除覆盖；远程图片无法安全读取像素时不额外取图或授权。
- 另取最多 48 个可见组件的局部像素，使用原 `analyze_wallpaper` 的平均色与亮度适配时钟／GitHub 的半透明背景、前景、次要文字、秒针及贡献色阶，覆盖所有尺寸及冻结拖拽画面。明确浅色／深色主题保持其明暗方向；跟随系统选项可按当地亮度选择，近似平局保持上次选择。桌面表盘移除固定白色内盘，启用增强时背景略微模糊，不加装饰外框／外发光；关闭或失败恢复原 CSS 变量和主题底色。三类区域合计上限 160，单块仍最多 256×64；这部分只修改调用和显示逻辑，没有修改或重新生成 WASM。
- 一个按需 Worker，解码并发 2、排队最多 64、派生缓存总计最多 32，其中壁纸最多 2；局部分析只保留最新一帧待处理像素，旧请求取消且不发布过期结果。12 秒超时回退，空闲 5 秒释放 Worker。对象 URL 在切换或卸载时回收。
- 常规 `npm test` 和两种构建均先校验预编译 WASM 与 Rust 源码的校验和；`npm run build:wasm` 使用固定工具链重建，普通使用者无需安装 Rust。
- CSP 仅增加包内 Worker、WASM 编译和本地 Blob 读取所需声明；图片桥接只接受同源 Blob 或精确内置图片路径。没有新增主机权限和远程代码来源。
