# 同步密码轮换

2026-11-24，第一项独立实现；备份密码、便笺历史和定时备份不在本提交中实现。

业务 IndexedDB 使用设备随机密钥，不是同步密码；轮换不替换设备密钥。需要更换的是云端同步内容、块、索引，以及本机密码绑定的凭据封套和同步暂存密文。`.covelet` 仍使用独立备份密码，不保存明文密码。

## 先校验，再切换

要求本机和云端同步完成、没有待上传版本或未处理冲突。取得同步锁，验证当前密码，逐个读取所有保留索引及其引用块，检查文件名摘要、认证解密、明文长度/摘要、业务字段和既有容量边界。任何失败都停止，不改变有效本机或云端数据。

新密文在独立的 `key-<随机128位标识>/all-data-v1` 目录准备，全部块独立使用原 PBKDF2-SHA256 210,000 次 + AES-256-GCM，新文件名和全部引用重建。全部回读校验后才切换。原目录的数据仍保持可恢复，不能在验证前覆盖或删除。

## 权威世代与中断恢复

在当前保存目录中使用固定的 `password-epoch-v1.json` 创建一次的后继链接作为提交点，链接路由到新世代；并发轮换只有一次创建能成功。链接包含绑定同步目标、前世代和新世代的认证加密证明。读端遍历后继链，只接受最后有效世代的密码。链接放在 `all-data-v1` 的父目录，以兼容 GitHub 既有 v2 封印文件。

候选上传前，设备加密存储保存轮换日志，内含新凭据封套、候选引用和阶段，不保存新旧密码。上传结果未知时以同一密文读回确认。切换后必须完成本机同步检查点、凭据封套和日志收尾，失败时保持锁定，使用新密码重试恢复。有效本机数据从不因日志重放被替换。

旧权威目录在切换后追加一个有效快照命名、以新密码加密但旧客户端不支持的围栏对象。旧客户端会在解密/格式检查停止，不能把旧格式当成新空目录继续同步。已经开始的旧客户端写入可能留在旧目录；它自己的本机内容仍在，升级并用新密码重新连接后按记录审阅合并，不能谎称能撤销已完成的远端请求。

成功后清除所有会话解锁信息、旧预览，必须由用户重新输入新密码解锁。其他设备的旧封套不能继续声明解锁成功：先检查有效世代；必要时重新输入该设备的存储访问凭据，再以新密码重封。本机未同步内容保留，世代变化后通过保守记录合并审阅。

## 可承诺的失效范围

旧密码不能解锁本机新的同步封套或读取当前权威同步版本。已下载文件、旧云端归档、存储服务版本历史和 Git 历史无法被密码更换追溯撤销；不承诺远程擦除既有副本。原世代归档不会作为当前同步数据使用。若需要撤销存储访问凭据，须在用户自备存储服务中另行处理，此功能不改变第三方账户凭据。

## 验证

覆盖错误当前密码、损坏历史块零发布、未同步/冲突拒绝、完整候选验证、并发提交、未知回复、重启恢复、旧密码拒绝、新密码显式解锁、其他设备重新绑定、原子本机提交失败。完成 `npm test`、`npm run build:unpacked` 后单独提交，并记录浏览器/真实服务验证边界。
