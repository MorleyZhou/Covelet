## True-cloud E2E: BLOCKED

No usable 坚果云 / Nextcloud credentials were found in this repository's local
environment-file names or the current process's provider environment variables.
Existing verification also records that dedicated test accounts are unavailable.
No credentials, private browser profiles or OS credential stores were read, and
no live-account requests were made. A real endpoint, dedicated test account / app
password and isolated pre-created directory are required to unblock this gate.

Use two physical machines with independent Chrome profiles for the final pass.
Two isolated profiles on one machine are a useful preliminary check, but do not
satisfy the dual-machine gate. Load the same unpacked build and use synthetic
content only:

1. Create a dedicated HTTPS WebDAV folder in 坚果云 or Nextcloud. Enter the same
   base URL, save directory and sync password in both profiles. Keep the app
   password and sync password outside logs, screenshots, Git and PR attachments.
2. On A, select WebDAV, enter minimal fields, and Test before entering a sync
   password. Confirm the result says directory-read only. Save-only must not
   create a remote object; locking and unlocking must show unverified credentials.
3. Complete A's first sync with a few synthetic shortcuts, a note and an image.
   On B, test and sync into an empty local profile. Compare the records and image
   bytes. Edit on B, sync, then sync A and compare the exact record.
4. Disconnect both machines, edit different fields of the same note on A and B,
   reconnect, then sync A and B. B must retain its whole local note until an
   explicit local / remote choice. Choose one full record, sync both machines and
   confirm convergence without synthesized fields. Repeat with the other choice
   and with delete versus edit.
5. Try wrong app password (401), denied folder access (403), missing directory
   (404), offline / timeout, and wrong sync password against existing ciphertext.
   Confirm readable errors, unchanged local data, retry and local-only fallback.
   Exercise certificate / host failures only on a test endpoint you control.
6. Restart each browser completely. Secrets must be absent; re-enter credentials
   and the same sync password, unlock and sync. Repeat an unchanged sync and
   inspect provider requests for zero new PUTs. Verify only the selected storage
   endpoint receives sync data; disclosed independent network features remain.

Record provider, build SHA, machine/profile separation, pass/fail per step and
redacted evidence. Keep **自备存储同步（Beta）** until this real dual-machine path
passes. R2, OSS, GitHub and GitLab remain Beta independently of WebDAV results.
