# 0.2.2 → 0.3.0 升级回归

状态：**PASS，2026-11-05**。已发布 0.3.0 控制组与当前构建各 **8 passed / 0 failed / 0 skipped / 0 flaky**，均无重试，各约 2.3 分钟。
本轮没有发现需要修改产品代码的升级缺陷；修正了测试加载生命周期、离线响应和历史界面的准备方式。已送审的安装包保持原样。

## 测试方式

在临时、独立的 Chromium 浏览器配置中加载实际 0.2.2 扩展，通过旧版 UI
创建合成内容。关闭旧浏览器后，在同一扩展路径替换为新版构建，并使用
同一配置重新启动。扩展 ID、浏览器配置、原加密数据库和设备密钥必须连续。
不能以新配置中的首次安装代替升级。

仅替换文件并重新启动可能让旧 Service Worker 缓存继续执行，即使原生
`getManifest()` 已返回 0.3.0。本夹具通过 Chrome 原生 CDP
`Extensions.loadUnpacked` 安装相同路径的新程序，不卸载或清空数据，并检查
实际新后台已移除旧 `alarms.onAlarm` 监听。之后的再次重启不强制安装，以验证正常启动。

测试文件：[内容与恢复](../../app/tests/upgrade/content.spec.mjs)、[故障与离线](../../app/tests/upgrade/failure.spec.mjs)、
[隐藏密码与旧提醒](../../app/tests/upgrade/privacy-clock.spec.mjs)、[同步状态](../../app/tests/upgrade/sync.spec.mjs)。
夹具由 [upgrade.fixture.mjs](../../app/tests/upgrade/upgrade.fixture.mjs) 提供。
默认使用当前新版构建；`COVELET_UPGRADE_TARGET=release` 用于已发布 0.3.0
的控制组。两种目标的结果分别记录，不互相代替。

## 边界

事务中止是受控故障注入，不代表自然磁盘故障或配额耗尽的统计结果。
离线用例验证本机读写，不要求 Bing 壁纸成功，也不声称云同步已验收。
本组测试不使用真实用户配置或凭据，不修改已发布 ZIP，不提交商店。

仅旧提醒专例把旧版已声明的可选 `notifications` 在其临时旧副本中预先授予，
以便旧 UI 使用真实权限 API 创建原生提醒。缓存原包及新生产 manifest 不变，
其余七例的旧 manifest 完全原样。原生授权弹窗和 OS 通知实际送达没有验收。
本次 Windows 运行中 Chrome 原生安装器也清空了无关控制计划，因此本例只证明旧提醒退役和
数据保留，不把选择性删除归因于 Covelet；选择性清理仍仅由既有单元测试覆盖。

同步部分是合成 HTTPS 协议回归，不代表真 WebDAV 服务或物理双机验收，也没有
重跑 GitHub 真云。商店签名、实际自动下发及原生授权界面仍属独立验证范围。
