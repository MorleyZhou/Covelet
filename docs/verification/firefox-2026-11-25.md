## Playwright 原始验收：受工具限制，未通过

使用仓库 Playwright 1.64.1 提供的 Firefox 157.0（build 1555）。通过 Mozilla 原生调试协议成功临时加载扩展，Gecko ID 正确、后台 RUNNING，但 Playwright 在导航至真实 `moz-extension://` 页面时超时。没有以普通 HTTP 网页代替扩展。

已经在安装的 `omni.ja` 中确认 `chrome/juggler/content/content/JugglerFrameChild.jsm` 对 `moz-extension://` 提前返回，不创建页面代理；关闭请求拦截和调整等待事件也无法解决。[对应官方源码](https://github.com/microsoft/playwright/blob/main/browser_patches/firefox/juggler/content/JugglerFrameChild.jsm)、[官方扩展支持范围](https://playwright.dev/docs/chrome-extensions)。

`npm run test:firefox` 明确返回非零退出码并记录 `PLAYWRIGHT_FIREFOX_EXTENSIONS_UNSUPPORTED`。这项验收没有通过；下面的原生回归是单独的替代证据，不能改称 Playwright 核心用例通过。

## 真实 R2 同步回归：通过；WebDAV 暂缓

用户后续明确指示“暂不测试 WebDAV”，本轮停止并不把它列为通过。同步回归复用此前授权的本机 R2 专用测试配置，命令为 `npm run test:firefox:r2`；没有把访问密钥写进源码、日志、同步内容或本文。

两个独立 Firefox 配置连接真实 R2 的独立测试子目录，调用当前生产同步、加密、WASM 签名和存储 API。测试副本的桥接器只用于生成合成记录、调用领域操作及读取结果，服务端、网络、加密、IndexedDB、冲突检测与合并都未替换。服务端证书校验保持开启。

实测：

- 建立共同基线后，两边离线分别增加 1 条独有便笺和 1 条独有导航，并分别修改同一便笺的标题和正文。
- 真实并发冲突出现；预览含“两侧都改了”和“仅一边改了”记录。
- 应用合并并发布新快照后双向同步，两个设备的内容完全相同；3 条便笺、2 条导航均保留，同一便笺得到两侧分别修改的标题和正文。
- 同步快照排除本机凭据、解锁会话、语言、正文/高亮缓存及 RSS；锁定后错误密码被拒绝，正确密码可解锁并继续同步。

R2 测试数据是合成内容，云端仅保留独立 `firefox-native-*` 测试子目录内的加密对象。未对用户已有远端内容执行清理、恢复或覆盖。它是 R2 的真实服务验证，不能替代未执行的 WebDAV 验收。
