# 定时本机加密备份

2026-11-24；在同步密码轮换提交 c0e983c 之后独立实现。本项不实现便笺历史。

## 数据与密码

按用户明确选择，默认包含隐藏内容，只生成认证加密的 `.covelet` 文件。复用完整备份的当前内容、资源与校验边界，不包含存储访问凭据、隐藏密码、设备密钥、语言和同步会话。普通手动 JSON/ZIP 导出继续是未加密文件，并保留原有明确提示。

保持已有 `.covelet` v1 格式：PBKDF2-SHA256 600,000 次、AES-256-GCM、48 字节认证头、50 MiB 明文上限。用户设置时输入并确认独立备份密码，预派生一个随机盐对应的不可导出 AES 密钥；只在本机专用 IndexedDB 中保存密钥及盐，不保存密码。每份文件重新生成 96 位随机 IV。旧版离线备份读取器仍能用原密码从文件头独立导出密钥并解密。

保存密钥的事实须在设置中明确披露，不能声称后台无需密钥。密钥与目录句柄不进入同步、手动备份或日志。没有密码或可用本机原数据时，不提供绕过密码的可移植恢复入口。关闭自动备份清除本机句柄与后台加密密钥，已有文件保留。

## 目录与调度

只在用户主动点击选择目录时调用 `showDirectoryPicker({mode:'readwrite'})`，将返回的目录句柄序列化保存到专用本机 IndexedDB。后台不调用选择器或请求权限。`chrome.alarms` 承担每天/每周调度，扩展 Worker 启动、浏览器启动和安装事件恢复闹钟；不存在依赖新标签页常开的计时器或自建服务。

Worker 写入前仅 `queryPermission({mode:'readwrite'})`。若权限为 prompt/denied、目录不可用或浏览器不支持，停止并保存明确的设置错误，要求用户主动重新选择/授权。不能保证浏览器关闭或操作系统休眠时仍执行；恢复运行后补做一次到期任务，再安排下一次。浏览器权限持久化取决于版本与用户授权，不能伪装成持续文件系统服务。

## 三份轮换与失败恢复

每个配置有随机所有者标识、严格的专用文件名和包含 SHA-256/大小/时间的持久化文件账本。只处理账本里属于此配置的文件，不遍历删除目录中其他 `.covelet`、用户修改文件或其他文件。

先创建新加密文件、关闭写流，再回读大小和密文摘要。验证成功后持久化文件记录，然后删除最旧且摘要仍匹配的自有备份，最终保留最近三份。安全提交期间允许临时出现第四份；不提前删除好备份。失败保留已有好文件，记录待处理阶段并在重启/重试时恢复，不能把半个文件登记为成功。

跨页面与 Worker 的备份、配置、禁用操作使用同一 Web Lock；状态、句柄、密钥和账本在专用 IndexedDB 中以一个状态提交存储，避免混合配置。失败在设置中显示，保留上次成功时间、下次计划与重试入口；不会仅打印日志或吞掉错误。

## 验证要求

单元测试覆盖四次以上备份最终三份、每份可由独立密码读取、不同 IV、重启恢复、权限失效、写入/回读/删除/状态持久化失败、修改/非自有文件保护、关闭后无调度且清除密钥。完整运行 `npm test` 与 `npm run build:unpacked`，实际浏览器验证 Worker 运行和三份轮换，并注明是否使用原生外部目录或 OPFS 测试句柄。通过后单独提交，再开始便笺历史。

相关平台边界依据：[Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)、[File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[持久目录权限](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api)。
