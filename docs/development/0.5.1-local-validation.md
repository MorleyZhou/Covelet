## 修复

- 选择“以本地为准”，用当前本地的可同步数据替换云端数据。
- 选择“以云端为准”，用云端的可同步数据替换本地数据。
- 另一台设备重建同步数据后，旧设备的离线修改或中断上传不会再吞掉本次明确的覆盖选择。
- 后台同步中断后，改选另一端会启动新的覆盖任务；已成功覆盖但响应丢失后，选择云端会读取最新云端内容。
- GitHub 返回的权限、限流、服务错误及同步目录含其他文件的情况，分别显示对应提示，避免误报数据格式错误。
- 设备密钥、连接凭据与本机隐藏状态继续保存在本机。
- 随机壁纸记录已经展示过的图片，一轮用完后再开始下一轮，刷新或重开页面保留轮换进度。
- Bing 合并最近与较早的两页官方归档，并按实际图片标识去重；图库仍受 Bing 可用近期归档限制。
- Wikimedia Commons 从官方接口分页获取符合尺寸、格式与许可条件的横图，不再只轮换原有四张。当前搜索限定 CC0，解析同时验证许可与来源，并保留作者及文件页链接。
- Commons 信息与图片分别按需授权 `https://commons.wikimedia.org`、`https://upload.wikimedia.org`；缓存、已展示记录及目录信息继续使用加密本地存储。下载、解码或保存失败时保留旧图及轮换进度。

## 数据格式提示说明

原提示并不只表示加密业务数据格式有问题：GitHub 写入被拒绝时，HTTP 200 内的 GraphQL 错误原先也会被归为“云存储返回的数据格式无效”。旧同步目录中的 README 等其他文件还会在覆盖目录的保护检查中触发相同提示，而普通读取会忽略它们。因此，全新设备能读取同一份云端内容，与旧设备在覆盖时遇到该提示并不矛盾。

本次用合成协议数据复现了这些路径；没有读取用户的云端响应，无法确认截图对应哪一种情况。覆盖操作保留并发校验，目录内的非同步文件仍受保护。
