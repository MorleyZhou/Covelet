## 一、用 WebDAV 做自定义存储同步

### 这是什么

Covelet 没有业务服务器，也不替你中转密文。跨设备时，把加密后的桌面数据直接传到你自己的 HTTPS WebDAV（常见：坚果云、Nextcloud）。同步默认关闭。浏览器原生 `storage.sync` 已停用。

### 开始前准备

1. 在 WebDAV 服务商开通 WebDAV，并拿到**应用密码**（不要用网页登录密码）。
2. 记下 HTTPS 基目录地址。坚果云示例占位：`https://dav.jianguoyun.com/dav/`（以你账号实际地址为准）。
3. **先在基目录里建好保存目录**。Covelet 不会替你建目录；测连也只读目录，不创建路径。
4. 准备一条至少 12 个字符的**同步密码**（与 WebDAV 应用密码不是同一把）。其他设备必须用同一目标、同一目录、同一同步密码。

### 三步设置

入口：**设置 → 数据 → 自定义存储同步**（原「全部扩展／数据同步」入口仍可用）。

1. **选择渠道**  
   选 WebDAV（默认推荐）。其他渠道标为 Beta，本文不写操作细则。

2. **测试连接**  
   填写：WebDAV 基目录地址、保存目录、用户名、WebDAV 应用密码。  
   点「测试连接」。  
   测连只检查登录和目录读取，**不写入文件、不验证同步密码、不开启自动同步**。  
   测连通过后才能进入下一步。改了地址或凭据，通过状态会失效，需要重测。

3. **密码与首次同步**  
   填写同步密码，点「保存并首次同步」。  
   这时才会真正校验写入权限和同步密码，并做第一次加密上传。  
   失败会停在第三步，可重试，或选「仅在本机使用」（关掉同步，本机数据保留）。

可选：第三步的「保存配置」只把配置留在本机会话侧，**不测连、不首次同步、不开自动同步**。

### 保存 ≠ 已验证

| 动作 | 实际含义 |
| --- | --- |
| 保存配置 | 本机记下配置；连接未验证 |
| 测试连接通过 | 当前凭据能读到该目录；不等于已写入、不等于同步密码正确 |
| 保存并首次同步成功 | 写入与同步密码已在本次流程里校验过 |
| 立即同步 | 在已解锁且连接匹配时再同步一次 |

界面也会写：「配置已保存；当前凭据的连接尚未验证。」以测连／首次同步结果为准，不要把「保存」当成「已通」。

### 重启后要重填凭据：这是设计，不是 bug

访问凭据和同步密码只放在当前浏览器会话（`chrome.storage.session`），不进本机持久业务数据、不同步进同步包、也不进 JSON／ZIP 导出。

因此以下情况都要重新输入凭据和同步密码来「解锁」：

- 关掉／重启浏览器
- 重新加载扩展
- 手动锁定

解锁后可用「立即同步」。自动同步默认关；开启后也只在 Covelet 页面打开且已解锁时跑，关页面不会在后台偷偷同步。

### 多设备冲突

同一条记录两边都改过时，不会静默合并字段。需要整条二选一：「整条保留本机」或「整条采用远端」。未处理前本机可见内容保留。不同记录可以各自推进。

### 常见问题（WebDAV）

- **401**：核对用户名和应用密码；不要填网页登录密码。
- **403**：账号是否启用 WebDAV，以及该目录是否有读写权限。
- **404／409**：基目录或保存目录路径不对；保存目录要事先建好。
- **测连过了，首次同步失败**：测连不验写入和同步密码；按第三步报错重试，或先「仅在本机使用」。
- **重启后又要输一遍**：预期行为，见上一节。

## 二、导入书签 HTML

### 这是什么

把 Chrome／Firefox／Edge 导出的 Netscape 书签 HTML，在本机解析后加到 Covelet 桌面。不上传文件，不新增账号或分析。

### 步骤

1. 在浏览器里导出书签为 HTML。
2. 打开 Covelet：**设置 → 数据 → 导入网址与书签 HTML → 导入书签 HTML 文件**。
3. 选文件。预览里会看到将要写入的文件夹路径、无效地址、重复数量。
4. 默认勾选「跳过桌面中已有和本次重复的网址」。需要副本时再取消勾选（取消后只追加副本，**不会覆盖**已有条目的名称、图标、位置等）。
5. 确认导入。新站点用名称字母图标；本流程不主动去拉网站图标。

嵌套文件夹会收成 Covelet 单层文件夹路径（例如 `Bookmarks bar / 开发 / 参考`）。空文件夹不会创建。

### 冲突默认：保留本地

重复判定按规范化网址，覆盖整张桌面和本批选中项。默认跳过重复，已有条目原样保留。预览和完成后都会标出跳过的重复数。

### 不会导入什么

`javascript:`、`data:`、浏览器内部地址、带登录凭据的网址等会进「无效地址」列表，不会变成桌面链接。

文件过大、层级过深、空文件或无关文件会给出本地错误提示；换文件后旧预览清空，避免误点导入。

### 和同步的关系

导入只改本机加密桌面数据。若已开启自定义存储同步，之后按你的同步设置上传；导入本身不发起 WebDAV 请求。

## English（same scope · draft）

### WebDAV sync

Covelet has no product server and does not relay ciphertext. Optional sync sends encrypted desktop data straight to your HTTPS WebDAV (e.g. Nutstore / Nextcloud). Sync is off by default. Browser `storage.sync` is disabled.

**Before you start.** Enable WebDAV at the provider, create an **app password** (not the web login password), note the HTTPS base URL, and **create the save folder under that base first**. Pick a sync password of at least 12 characters. Other devices need the same target, folder, and sync password.

**Path:** Settings → Data → Custom storage sync.

1. **Choose channel** — WebDAV (recommended). Other channels are Beta; this how-to skips them.
2. **Test connection** — base URL, save folder, username, app password. Test checks login and folder read only. It does not write, does not check the sync password, and does not turn on auto-sync. Changing target or credentials clears a prior pass.
3. **Password and first sync** — enter the sync password, then **Save and first sync**. That step checks write access and the sync password. On failure, retry or choose **Use on this device only**.

**Save ≠ verified.** Saving config only stores local settings. A passed test means the current credentials can read that folder. First sync success is when write access and the sync password were checked in that run.

**Re-enter credentials after restart — by design.** Credentials and the sync password live in the browser session only. After a browser restart, extension reload, or manual lock, unlock again. This is intentional, not a bug. Auto-sync (off by default) runs only while a Covelet page is open and unlocked.

**Conflicts.** Same record edited on two devices: choose the whole local record or the whole remote record. No silent field merge.

### Bookmark HTML import

**Path:** Settings → Data → Import URLs and bookmark HTML → Import bookmark HTML file.

Supports Chrome / Firefox / Edge Netscape HTML. Parsing stays on device. Preview shows destinations, rejected URLs, and duplicate counts before you confirm.

**Conflict default: keep local.** “Skip URLs already on the desktop or duplicated in this batch” is on by default. Existing IDs, names, artwork, and positions stay put. Turning the checkbox off only appends copies; it never overwrites an existing entry.

Unsafe or unsupported URLs stay in the rejected list. Import does not fetch site icons in this flow. If custom sync is on, later syncs follow your sync settings; the import itself does not call WebDAV.
