# 自定义存储同步

更新日期：2026 年 10 月 31 日。本文适用于0.2.2 开发候选，不表示已经发布、通过商店审核或完成真实云账号验收。统一同步已取代原来分开的导航配置同步和便笺／稍后读同步；浏览器原生同步已停用。**WebDAV 是本轮加固路径，真实坚果云／Nextcloud 账号验收仍待完成；其他四项服务已实现但均为 Beta，未通过真实云账号验收。**

## 连接与运行

入口为设置 → 数据 → 自定义存储同步，也可使用原扩展 → 全部扩展／数据同步入口。无需 Covelet 账号，不经过 Covelet 服务器，所有数据在本机加密后直接发往用户选择的存储。

| 渠道 | 状态 | 需要准备的连接 |
| --- | --- | --- |
| GitHub | Beta（未真实云验收） | 专用私有仓库、已有分支、保存目录、具备该仓库 Contents 读写权限的令牌 |
| GitLab | Beta（未真实云验收） | HTTPS 服务地址、项目 ID 或完整路径、已有分支、保存目录、具备所需 API 写权限的专用令牌 |
| HTTPS WebDAV | P0 加固路径（真实云验收待完成） | 基目录、已创建的保存目录、用户名与应用密码，可连接坚果云或自己的 Nextcloud 等兼容服务 |
| Cloudflare R2 | Beta（未真实云验收） | 账户 S3 API 地址、Bucket、保存目录、仅限目标 Bucket 的对象读写凭据 |
| 阿里云 OSS | Beta（未真实云验收） | Bucket HTTPS 域名、Bucket、地域、保存目录、受限 RAM 凭据或临时令牌 |

服务商空间、请求频率、文件数量及费用由账号套餐决定。Covelet 不提供存储空间，也不把任一渠道描述为无限或永久免费。历史查询来源仅供继续核查：[GitHub 套餐](https://docs.github.com/en/get-started/learning-about-github/githubs-plans)、[GitLab 存储](https://docs.gitlab.com/user/storage_usage_quotas/)、[坚果云 WebDAV](https://help.jianguoyun.com/?p=2064)、[R2 价格](https://developers.cloudflare.com/r2/pricing/)。

1. 在服务商处准备专用存储与受限凭据。WebDAV 需要先创建所填保存目录；不支持公共分享链接的特殊认证方式。Git 托管服务使用文件 API，会生成仓库提交。
2. 引导第一步选择渠道，默认高亮并推荐 WebDAV；其余四项仍可选，明确标为 Beta。第二步仅显示所选渠道的连接字段，点击「测试连接」，无需填写同步密码。WebDAV 用 `Depth: 0` 的 `PROPFIND` 检查应用密码登录和保存目录读取；不会写入文件、建立目录、下载业务内容或保存配置。通过只表示本次目录读取成功，**不表示已验证写入或同步密码**。其他 Beta 渠道使用目录列举探测。测试通过后可进入第三步；修改目标或凭据会使通过状态失效。
3. 第三步填写至少 12 字符的独立同步密码（去除首尾空白计长度，最多 1024 UTF-8 字节），点击「保存并首次同步」。执行解密、原子导入及加密上传，写入权限和同步密码在此时实际校验。首次尝试期间不启用自动同步；只有控制器实际返回成功，才应用「首次同步成功后自动同步」的选择。失败保留在第三步，固定操作区上方显示中文错误，可重试或「仅在本机使用」。
4. 第三步也保留独立的「保存配置」：仅做本机校验与会话凭据保存，不联网、不执行测试或首次同步、不启用自动同步。API 仍允许未验证的配置保存／解锁，并明确显示未验证状态；引导要求先测试再继续。保存配置／解锁不等于已验证，更不等于已同步。测试结果只对应当时的目标与凭据；更改目标／凭据、重测失败、锁定或重启后须重新测试。保存后可用「立即同步」重试；不同记录可独立推进，同一记录冲突必须整条二选一。其他设备须使用相同目标、目录和同步密码。
5. 浏览器重启、扩展重新加载或手动锁定后，需要重新输入凭据及同步密码「解锁」。凭据、密码及当前连接测试结果仅保存在 `chrome.storage.session`，不进入本机持久业务记录、同步载荷或导出备份。网页预览只在内存保留秘密，不能发起真实云端同步。
6. 「解锁后自动同步」默认关闭。开启后，仅在 Covelet 页面打开且会话已解锁时工作；已提交变更约 15 秒后安排同步，页面可见时定时检查（约 60 秒），重新聚焦也会安排同步。关闭页面不会启动后台同步服务。自动同步也不能替用户解决整记录冲突。

WebDAV 错误会区分地址格式、401 用户名／应用密码、403 目录权限、404／409 路径缺失、离线、超时、TLS 证书及主机不可达。浏览器 `fetch` 有时只提供不透明的网络错误，此时提示检查网络／地址／证书／站点权限，不虚构具体原因。服务端响应正文、URL 和凭据不会进入错误文案。

## 统一的数据范围

同步从统一加密 IndexedDB 读取业务命名空间，不再为工具设置单独开关，包括：

- 导航、文件夹、搜索引擎、外观、布局、语言偏好和桌面组件配置。
- 所有内置扩展的持久数据：便笺、手动稍后读、工具回收站、时钟运行状态与通知开关、GitHub 贡献缓存。
- 本机命名桌面方案、恢复前副本、别名与隐私标记。
- 本地图像资源、导航图标、搜索引擎图标、Bing 壁纸及对应缓存记录。原始图片按二进制编解码，不用 Base64 充当本机存储。
- 后续扩展通过统一存储 API 保存的业务命名空间。该默认范围不会发现绕过统一 API 新建的任意数据库。

以下信息保留在本机，不通过全量同步传播：不可导出的设备密钥；隐藏密码验证记录、失败计数及重试状态；当前隐藏开关；同步连接、自动同步开关、目标信息、设备身份、合并与冲突元数据、待提交密文。访问凭据和同步密码仍仅存在于当前会话。未保存表单、布局选择、图片分析结果和其他页面内存不会因此变成持久同步内容。

隐私标记可同步，当前设备是否隐藏以及如何解锁由该设备自己决定；同步和冲突处理不关闭隐藏、不替换本机隐藏密码。各设备的站点与通知权限也不会随业务记录授予。时钟运行状态恢复后会在当前设备重建有效倒计时计划，实际通知仍受设备时间、运行状态及本机通知权限影响。

## 目录、迁入与旧版兼容

新的权威索引保存在所选目录的 `all-data-v1` 子目录，内容块位于 `all-data-v1/blobs`。索引使用 `covelet-all-data` 格式，包含完整同步文档的认证引用；索引、文档和图片块均为加密载荷，不向服务商提供明文业务内容。

只有首次目标还没有全量索引时，客户端才读取原导航目录和 `tools-v1` 中的旧导航／便笺／阅读内容，并与当前本机数据迁入新协议。一旦存在全量索引，后续同步只以新目录为权威，不反复把旧版内容合回，也不继续向旧协议发布新的导航修订。

其他设备须升级后再继续同步。旧客户端不能读取全量业务数据和图像，继续写入旧目录也不会自动进入新协议。旧云端文件不会自动删除，历史数据仍受服务商和其他设备的保留规则影响。

界面的「旧版导航历史」只浏览升级前留下的导航修订，并沿用旧导航差异／选择性恢复规则。它不是新协议的全量历史浏览器；新产生的扩展、图片及全量修订不会追加到该列表。恢复旧导航后，会作为当前业务数据的新编辑参与下一次全量同步。

## 加密、合并与失败处理

浏览器 Web Crypto 使用 PBKDF2-SHA256（210,000 次）从独立同步密码派生密钥，再以 AES-256-GCM 认证加密。各对象使用随机盐和 IV，本机设备密钥不上传；接收设备先校验、解密同步载荷，再用自己的设备密钥写入 IndexedDB。包内 `sync-core.wasm` 继续负责摘要、签名及既有计算辅助，不执行网络请求，也不载入远程或用户代码。

每台设备追加带随机设备标识、递增时钟和内容摘要的不可变索引。完整记录作为并发单位，不承诺对同一便笺集合、恢复点或其他整记录内部字段自动合并。不同设备同时修改或修改与删除竞争时，竞争版本均保留。**冲突 = whole-record choose-one（整条记录二选一）**：未处理时保留本机可见记录（含本机删除），不先静默应用排序胜者，也不拼接冲突载荷的内部字段。普通同步或编辑冲突记录均不视作选择；不同记录仍可同步。

「查看并选择版本」展示本机与指定远端的两侧内容及删除状态。选择「整条保留本机版本」或「整条采用远端版本」，再确认；会以选择的一整条内容生成新因果版本。多份远端版本可分别查看，选择其中一份会解决同条记录的全部竞争版本，不影响其他记录的未处理冲突。长内容明确标记预览截短，二进制内容展示字节数与类型，选择仍作用于完整数据；不远程渲染图片或执行内容。预览有效期十分钟，期间任何本机快照或冲突文档变化都要求重新预览。

明确选择也不会更改本机隐藏开关、隐藏密码或会话凭据。采用隐私标记记录时，其可同步字段按整条选定值替换，不执行旧版字段并集；若采用删除版本会移除当前隐藏内容的标记，须先在本机解除隐藏，失败时保留未解决冲突。

接收端完成所有引用、块摘要、解密、结构及领域校验后，才以当前本机快照摘要作比较并交换（CAS），在一个 IndexedDB 提交中原子应用。如果另一标签页已经修改了数据，本次不覆盖，提示重新同步。不会用部分下载或部分通过校验的数据替换本机。

待提交密文和文件名先在本机加密持久化。结果未知或请求失败时，下次先核对相同对象；同一内容重试复用已保存密文，不凭空生成重复提交。有待提交或未处理冲突时不能切换目标。锁定阻止新的请求，但已经发出的请求可能完成，不表示撤回了服务端写入。

## 容量与服务限制

全量载荷切成至多 **256 KiB 明文块** 后分别加密。当前业务及图片载荷总量上限 **128 MiB**，因果文档元数据上限 **8 MiB**，块数量至多 **2,000**；还设有 12,000 条记录、100 个设备及 2,000 条索引的安全边界。底层单个加密对象仍受 768 KiB／512 KiB 明文的保护限制，分块后的图片不会套用旧导航整文档 512 KiB 上限。

上述数值是多个同时适用的上限，并非可用空间承诺。冲突版本、历史、记录结构和图片会占用额度；服务商目录列举数量、仓库文件数量、浏览器本机空间和请求频率可能更早限制同步。达到边界时明确停止并保留本机数据，不把截断目录当成完整结果，也不自动删除远端历史。空间清理与历史轮换工具尚未实现，建议保留独立完整备份。

## 网络与验证边界

HTTPS 请求只访问所选且已授权的精确来源，不携带 Cookie／页面来源、不跟随重定向，无 Covelet 代理。服务商仍能观察连接 IP、时间、密文大小及文件名中的随机设备标识和版本；加密不等于匿名。当前没有同步密码找回或对现有云端数据重新加密的改密流程。

## 引导与本机回退

三步引导直接使用既有 `CloudSyncSettings`，不增加平行的同步栈。`app/src/lib/cloud-connection.js` 保留渠道顺序、Beta 名称、`SYNC_SETUP_STEPS` 和只读 `probeCloudConnection`，并提供 `finishCloudSetup` 编排既有保存与首次同步 API。控制器以返回状态表示失败，因此只有 `phase: saved` 算成功，不能把 Promise 正常返回当作已同步。

「仅在本机使用」在每一步及后续管理页均可用：清除共享会话凭据及连接测试结果、关闭自动同步，然后退出引导。本机业务数据、原目标、待上传密文和冲突保留，便于以后明确解锁重试；不会删除远端副本或撤回已经发出的请求。这里只关闭云同步，不改变已选 Bing 壁纸、搜索或手动图片获取等独立功能。

## 浏览器重启后继续同步

凭据和同步密码只保留在当前浏览器会话。浏览器完全退出、重启或点击「锁定」后，需在「设置 → 数据 → 自定义存储同步」重新输入 WebDAV 用户名、应用密码及相同的同步密码，再点「解锁」。这是保密设计，不是连接配置丢失。保存的地址和目录、本机数据、待上传版本与冲突仍保留；解锁不等于连接已验证，可先「测试连接」再「同步所有数据」。

两台设备都使用 0.2.2、同一基目录、保存目录和同步密码。同步默认关闭；先在一台设备完成首次同步，再在另一台测试和同步。两边已有不同内容时可能出现整条记录冲突，须查看两侧后明确选择。真实账号双机读写仍待验收。
