# 自备存储同步

更新日期为 2026 年 11 月 25 日。本文说明 **0.7.0** 的当前行为：统一同步已取代分开的导航与工具同步，浏览器原生同步已停用；冲突默认按记录预览合并，支持同步密码轮换。下文标注日期的旧验证仅作历史记录，不代表本版重新通过相应服务验收。早期结果见[收口记录](verification/0.3-closeout.md)。

## 连接与运行

入口为「扩展 → 自备存储同步」。数据在本机加密后直接发往用户选择的存储。[早期审计与真实云验收路径](verification/0.3-sync-proof-gap.md)。

| 渠道 | 状态 | 需要准备的连接 |
| --- | --- | --- |
| GitHub | 保留既有适配器及历史真服务记录；本版新增合并／换密由协议回归覆盖，未重新执行该服务实测 | 专用私有仓库、已有分支、保存目录、具备该仓库 Contents 读写权限的令牌 |
| GitLab | 保留既有适配器及历史真服务记录；本版未重新执行该服务实测 | HTTPS 服务地址、项目 ID 或完整路径、已有分支、保存目录、具备所需 API 写权限的专用令牌 |
| HTTPS WebDAV | 界面推荐入口；用户已暂缓本轮真实服务复验，历史报告不等于本版通过 | 基目录、已创建的保存目录、用户名与应用密码，可连接坚果云或自己的 Nextcloud 等兼容服务 |
| Cloudflare R2 | 已执行 Chrome／Edge 和 Firefox 双配置记录合并，以及 Chrome 同步换密的真实服务自动化验证 | 账户 S3 API 地址、Bucket、保存目录、仅限目标 Bucket 的对象读写凭据 |
| 阿里云 OSS | Beta，暂缓真云验收 | 从未开启版本控制的专用 Bucket HTTPS 域名、Bucket、地域、对象读写/列举及 GetBucketVersioning 权限 |

服务商空间、请求频率、文件数量及费用由账号套餐决定。Covelet 不提供存储空间，也不把任一渠道描述为无限或永久免费。历史查询来源仅供继续核查：[GitHub 套餐](https://docs.github.com/en/get-started/learning-about-github/githubs-plans)、[GitLab 存储](https://docs.gitlab.com/user/storage_usage_quotas/)、[坚果云 WebDAV](https://help.jianguoyun.com/?p=2064)、[R2 价格](https://developers.cloudflare.com/r2/pricing/)。

1. 在服务商处准备专用存储与受限凭据。WebDAV 需要先创建所填保存目录；不支持公共分享链接的特殊认证方式。Git 托管服务使用文件 API，会生成仓库提交。
2. 引导第一步选择渠道，默认高亮并推荐 WebDAV，OSS 单独标为 Beta。第二步仅显示所选渠道的连接字段，点击「测试连接」，无需填写同步密码。WebDAV 用 `Depth: 0` 的 `PROPFIND` 检查应用密码登录和保存目录读取；不会写入文件、建立目录、下载业务内容或保存配置。通过只表示本次目录读取成功，**不表示已验证写入或同步密码**。其他渠道使用目录列举探测。测试通过后可进入第三步；修改目标或凭据会使通过状态失效。
3. 第三步填写至少 12 字符的独立同步密码（去除首尾空白计长度，最多 1024 UTF-8 字节），点击「保存并同步」。保存后进入管理页，由后台验证写入权限与同步密码。失败时可在管理页查看原因并重试。若发现冲突，自动同步暂停，等待用户预览并应用记录级合并。
4. 第三步也保留独立的「保存配置」，在本机校验并加密保存访问凭据，保持原有的连接验证状态和手动同步设置。引导要求先测试再继续。测试结果只对应当时的目标与凭据。更改目标或凭据、重测失败、锁定或重启后，连接测试结果会失效。保存后可用「立即同步」重试。其他设备须使用相同目标、目录和同步密码。
5. 浏览器重启、扩展重新加载或手动锁定后，用当前同步密码解锁已保存的连接。本机保存的是加密凭据。同步密码、解密后的凭据和当前连接测试结果只在浏览器 `storage.session` 中使用，锁定或重启后清除。同步内容和导出备份均排除这些信息。其他设备遇到密码世代变化时，可能还需重新填写该设备的存储访问凭据。
6. 自动同步默认关闭。开启后，浏览器后台在连接解锁时定期检查，离开 Covelet 页面后也能继续。发现冲突时等待记录级预览确认。浏览器关闭时不执行；重新启动并解锁后接续未完成任务。

WebDAV 错误会区分地址格式、401 用户名／应用密码、403 目录权限、404／409 路径缺失、离线、超时、TLS 证书及主机不可达。浏览器 `fetch` 有时只提供不透明的网络错误，此时提示检查网络／地址／证书／站点权限，不虚构具体原因。服务端响应正文、URL 和凭据不会进入错误文案。

## 统一的数据范围

同步从统一加密 IndexedDB 读取业务命名空间，不再为工具设置单独开关，包括：

- 导航、文件夹、搜索引擎配置、外观、布局和桌面组件配置。语言偏好与当前选中的搜索引擎属于本机偏好，不同步。
- 便笺及其有界历史、稍后读链接、工具回收站、GitHub 贡献缓存等业务数据。旧时钟和旧标签集合可作为兼容数据保留，不恢复已移除的功能入口或通知调度。
- 已保存的旧版桌面方案、恢复前副本、别名与隐私标记。
- 本地图像资源、导航图标、搜索引擎图标、Bing 壁纸及对应缓存记录。原始图片按二进制编解码，不用 Base64 充当本机存储。
- 后续扩展通过统一存储 API 保存的业务命名空间。该默认范围不会发现绕过统一 API 新建的任意数据库。

以下信息只保留在本机：不可导出的设备密钥、隐藏密码验证记录和当前隐藏开关、同步连接和加密访问凭据、自动同步设置、设备身份、冲突元数据及待提交密文，以及语言／搜索引擎选择、文章正文与高亮缓存、阅读样式、RSS 订阅／收件箱和新本机会话。定时备份的目录句柄与后台加密密钥位于独立本机数据库，也不参与同步。同步密码和解密后的凭据只在当前会话中使用。

隐私标记可同步，当前设备是否隐藏以及如何解锁由该设备自己决定；同步和冲突处理不关闭隐藏、不替换本机隐藏密码。站点及浏览器来源授权不会随业务记录授予。0.7.0 可选的 tabs／history／bookmarks 仅供用户主动使用命令面板和本机会话，不是同步所需权限，浏览器搜索结果不进入同步。

文章／高亮、RSS 和本机会话使用设备密钥加密存储，但也不进入现有完整备份；不要把完整备份理解为所有本机数据库的镜像。公开阅读内容可另行导出为未加密 Markdown，隐藏内容被排除。便笺历史属于便笺业务内容，会进入同步及新版完整备份。详见[本机阅读范围](local-reading-library.md)、[本机会话](browser-command-palette.md)、[定时加密备份](scheduled-local-backups.md)。

## 目录、迁入与旧版兼容

初始权威索引保存在所选目录的 `all-data-v1` 子目录，内容块位于 `all-data-v1/blobs`。沿用已有 GitHub 封印／迁移布局的连接按原协议解析其有效目录。索引使用 `covelet-all-data` 格式，包含完整同步文档的认证引用；索引、文档和图片块均为加密载荷，不向服务商提供明文业务内容。修改同步密码后，固定后继链接将客户端路由到独立的新密钥世代目录，格式与加密算法仍复用现有协议。

只有首次目标还没有全量索引时，客户端才读取原导航目录和 `tools-v1` 中的旧导航／便笺／阅读内容，并与当前本机数据迁入新协议。一旦存在全量索引，后续同步只以新目录为权威，不反复把旧版内容合回，也不继续向旧协议发布新的导航修订。

其他设备须升级后再继续同步。旧客户端不能读取全量业务数据和图像，继续写入旧目录也不会自动进入新协议。旧云端文件不会自动删除，历史数据仍受服务商和其他设备的保留规则影响。

界面的「旧版导航历史」只读浏览升级前留下的导航修订，不提供恢复入口。它不是新协议的全量历史浏览器；新产生的扩展、图片及全量修订不会追加到该列表。0.7.0 的便笺历史和本机会话是独立功能，不复活旧导航／标签历史恢复。

## 加密、合并与失败处理

浏览器 Web Crypto 使用 PBKDF2-SHA256（210,000 次）从独立同步密码派生密钥，再以 AES-256-GCM 认证加密。各对象使用随机盐和 IV，本机设备密钥不上传；接收设备先校验、解密同步载荷，再用自己的设备密钥写入 IndexedDB。包内 `sync-core.wasm` 继续负责摘要、签名及既有计算辅助，不执行网络请求，也不载入远程或用户代码。

每台设备追加带随机设备标识、递增时钟和内容摘要的不可变索引。检测并发修改后保留本机现状，先生成业务记录级合并预览；导航项、文件夹、便笺、稍后读、标签及支持的外观设置按各类规则处理，两侧独有记录不会因默认整份选边被移除。

在标有「有冲突」的同步记录上点击「预览合并」，查看「两侧都改了／仅一边改了／一边删了」，可逐条选择本机、云端或合并结果，再明确应用。同一字段竞争仍需审阅；删除与修改竞争默认保留修改，可信共同基线不存在时保守保留两侧独有身份。便笺正文与富文本文档、导航位置等关联字段作为一组处理，不能任意拼接。具体规则见[记录级合并设计](record-level-sync-merge.md)。

应用前在本机保留恢复前副本；「撤销上次合并」会核对应用后的快照，若已有后续修改则停止，避免覆盖较新内容。撤销不会远程抹除已经发布或被其他设备读取的副本。记录选择、合并和撤销均不关闭隐藏、不更换隐藏密码或会话凭据；涉及当前隐藏内容的破坏性选择会要求先解锁，失败时保留未解决冲突。

接收端完成所有引用、块摘要、解密、结构及领域校验后，才以当前本机快照摘要作比较并交换（CAS），在一个 IndexedDB 提交中原子应用。如果另一标签页已经修改了数据，本次不覆盖，提示重新同步。不会用部分下载或部分通过校验的数据替换本机。

待提交密文和文件名先在本机加密持久化。结果未知或请求失败时，下次先核对相同对象；同一内容重试复用已保存密文，不凭空生成重复提交。有待提交或未处理冲突时不能切换目标。锁定阻止新的请求，但已经发出的请求可能完成，不表示撤回了服务端写入。

## 容量与服务限制

全量载荷切成至多 **256 KiB 明文块** 后分别加密。当前业务及图片载荷总量上限 **128 MiB**，因果文档元数据上限 **8 MiB**，块数量至多 **2,000**；还设有 12,000 条记录、100 个设备及 2,000 条索引的安全边界。底层单个加密对象仍受 768 KiB／512 KiB 明文的保护限制，分块后的图片不会套用旧导航整文档 512 KiB 上限。

上述数值是多个同时适用的上限，并非可用空间承诺。冲突版本、历史、记录结构和图片会占用额度；服务商目录列举数量、仓库文件数量、浏览器本机空间和请求频率可能更早限制同步。达到边界时明确停止并保留本机数据，不把截断目录当成完整结果，不静默丢弃业务记录。Git 提交历史中的数据仍可能占用仓库空间。

## 修改同步密码

先完成同步并处理冲突，再选择「修改同步密码」，填写当前密码、新密码和确认。客户端逐一校验保留的索引及内容引用，使用新密码在独立世代中重建加密块和索引；回读通过后才切换当前权威目录，并清理本机密码绑定的暂存密文与旧会话。中断时保留加密日志并锁定连接，以新密码显式解锁完成恢复。设备加密密钥和独立的备份密码不随之更改。

旧密码不能解锁新的本机同步凭据封套或读取当前新世代；旧云端归档、服务商版本历史、Git 历史及已下载文件无法追溯撤销，不承诺远程擦除。其他设备需升级并以新密码重新连接，必要时重新填写各自的服务访问凭据；未同步的本机内容保留后再审阅合并。协议、失败阶段和已发出旧请求的边界见[同步密码轮换设计](sync-password-rotation.md)。

## 网络与验证边界

HTTPS 请求只访问所选且已授权的精确来源，不携带 Cookie／页面来源、不跟随重定向，无 Covelet 代理。服务商仍能观察连接 IP、时间、密文大小及文件名中的随机设备标识和版本；加密不等于匿名。支持上述主动换密，但没有密码找回或绕过密码的恢复入口。

0.7.0 的新功能真实服务证据为 R2：[Chrome／Edge 合并](verification/record-merge-browser-r2-2026-11-24.md)、[同步换密](verification/password-rotation-2026-11-24.md)、[Firefox 原生核心与 R2](verification/firefox-2026-11-25.md)。这些是隔离配置与合成数据的自动化验证，不等于完整人工验收，也不代表本版已对五种渠道全部复验。WebDAV 已按用户要求暂缓真实服务复验。Chrome／Edge 使用 service worker，Firefox MV3 使用事件页面；Firefox 是未签名开发预览，分发与平台限制见[兼容性说明](firefox-compatibility.md)。

本机阅读器只在用户添加／改址或明确提取原文时按精确授权读取网页，失败保留链接；图片逐张点击加载。RSS 仅定期请求用户已添加并授权的来源，不批量抓取文章或图片。这些功能的来源及可选 tabs／history／bookmarks 授权不由同步传播。没有请求日志或遥测，不能给出虚构的零联网次数。

## 引导与本机回退

三步引导直接使用既有 `CloudSyncSettings`，不增加平行的同步栈。`app/src/lib/cloud-connection.js` 保留渠道顺序、Beta 名称、`SYNC_SETUP_STEPS` 和只读 `probeCloudConnection`，并提供 `finishCloudSetup` 编排既有保存与首次同步 API。控制器以返回状态表示失败，因此只有 `phase: saved` 算成功，不能把 Promise 正常返回当作已同步。

「仅在本机使用」在每一步及后续管理页均可用：清除共享会话凭据及连接测试结果、关闭自动同步，然后退出引导。本机业务数据、原目标、待上传密文和冲突保留，便于以后明确解锁重试；不会删除远端副本或撤回已经发出的请求。这里只关闭云同步，不改变已选 Bing 壁纸、搜索或手动图片获取等独立功能。

## 隐私自查与早期验证记录

## 浏览器重启后继续同步

打开「扩展 → 自备存储同步」，输入原来的同步密码，再点「解锁」。从旧版本升级且尚未保存加密凭据时，需补填一次访问凭据并完成同步。解锁后可用「测试连接」检查目录读取，也可用「立即同步」直接重试。

两台设备使用支持记录级合并的 Covelet，并设置同一目标、目录和当前同步密码。先在一台设备完成首次同步，再在另一台测试和同步。如果同步记录标有「有冲突」，点击「预览合并」逐条审阅并确认，不再默认整份二选一。修改过同步密码的目标须使用新密码，并按提示重新绑定该设备的服务访问凭据。
