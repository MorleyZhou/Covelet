# 组件弹窗与 Folio

2026-10-21 Covelet 开发源码。按用户要求，本项目只修改功能、安装依赖及生成翻译资源，未运行测试、静态检查、应用构建或浏览器验收。Folio 上游补丁发布单独执行其既有发布门禁，见下文。本轮没有改写 Covelet 冻结发布包、商店提交或在线隐私政策。

## 弹窗

时钟、便笺、稍后读及扩展中心共用最大化／还原按钮。最大化将同一个原生 dialog 扩展到视口内，不使用浏览器全屏 API、不新增权限、不重新挂载工具，编辑内容、计时与当前分类继续留在原组件。关闭及放弃未保存内容的确认保留。

统一为标题操作区与内部滚动区域；表单和网格允许缩小，长内容通过对应滚动区访问。补齐只供辅助技术读取的标签样式，避免便笺名称标签作为普通正文外露。便笺列表、正文及扩展配置区各自保留滚动空间，不再用可拉伸 textarea 占满并挤压保存按钮。

按后续反馈减少边框：便笺标题、正文和搜索获得焦点时不再出现包围轮廓，取消编辑工具栏分隔线。标题、搜索、列表和次要操作采用轻微底色区分键盘焦点，正文保留插入光标；不全局清空焦点样式，保留表格单元格、复选框等有功能意义的边界。此样式调整仍未运行 Covelet 测试、检查、构建或浏览器验收。

Folio 的浮层容器直接使用所属 dialog，绕开正文滚动区的裁切；仍属于原生弹窗顶层与焦点范围。最大化沿用现有编辑器实例，预览切换也保留编辑器，避免切换时清除撤销历史。功能是源码实现，尚未做浏览器交互验收。

后续提示改为独立弹窗：放弃未保存内容、切换便笺、删除便笺／稍后读、删除或打开标签快照、恢复云端版本，都通过共享 `PromptDialog` 进入单独的原生顶层 dialog，不再向原工作区插入确认卡片。默认焦点是取消，Esc 或点击遮罩可取消；执行期间禁止重复确认和关闭，结束后恢复焦点。浮层位于所属弹窗内、表单与滚动区之外，继承主题并阻断事件穿透；初次挂载时等待所属窗口打开后再显示提示。

工具错误与操作结果使用可关闭的 `MessageDialog`；Folio 的重复行内错误由宿主弹窗接管。跨页面内容冲突通过提示弹窗告知，原有底部主操作改为“重新打开”，仍要确认放弃未保存草稿，保留修订校验。持续同步进度不弹出阻塞窗口。提示和工具栏调整均为本项目源码及翻译资源改动，不需要再发布 Folio，也未运行测试、检查、构建或浏览器验收。

## 编辑器

依赖固定为 `@futelab/folio@0.2.1`，使用 `FolioEditor`、`FolioReader`、浏览器 Markdown 导入及核心文档校验。库随安装包提供，不使用远程脚本、远程 WASM 或编辑器服务器。[Folio 源码与接入文档](https://github.com/futelab/folio)；MIT 许可随 `app/public/FOLIO_LICENSE.txt` 提供。

- 便笺支持 Folio 的富文本块、斜杠命令、选区格式、表格和文档查找替换；通过 `ui.toolbar=false` 隐藏 Folio 顶部工具栏，保留正文菜单与撤销、重做、查找等快捷键。沿用便笺的标题、置顶、预览、复制、手动保存和删除确认。
- 与 Covelet 的浅／深主题及八种界面语言衔接；仅翻译编辑器菜单和静态标签，不翻译用户文档。
- 普通文字／旧 Markdown 在打开时转换为内存文档，遇到不支持的旧内容则保留为可编辑的原始文字。转换不会自动写入存储；用户保存才保存富文本。
- Folio JSON 保存格式，纯文字投影继续供桌面摘要、既有 WASM 搜索与统计使用，不把富文本强行转换回 Markdown 而丢失格式。
- 保留记录修订检查、跨页面冲突提示及关闭／切换未保存便笺的确认。超过大小或文档校验失败时阻止保存，保留草稿供用户修改，不用空文档覆盖旧记录。
- 不接入协作、账号或图片上传服务；文档中的图片会按其地址向对应站点请求，不承诺图片访问匿名。正文、图片地址及富文本文档仍仅属于本机工具数据，不加入导航同步。

## 数据兼容

继续使用原来的本机键 `covelet.tools.v1` 及独立 demo 键，避免更换键后遗失既有内容。记录内部版本升级到 `2`，读取支持原版 `1` 的纯文本便笺；读取本身不写盘。下一次用户工具操作正常保存时采用版本 `2`。便笺新增可选 `document` 字段，`body` 是对应的文字投影，加载时检查二者一致。

工具导出改为版本 `2` 的紧凑 JSON，包含完整 Folio 文档；仍可导入版本 `1` 的旧备份，按原规则只合并新 ID，不覆盖本机编辑。紧凑导出避免富文本缩进让本应用导出的文件超出导入限制。旧开发构建不能读取版本 `2`，不宣称新富文本对旧构建向前兼容。

保留 200 条便笺、每条正文 60000 个 UTF-16 单元、全部工具 4 MiB、备份导入 5 MiB 的限制。另将单篇 Folio 文档限制为 512 KiB、2000 个节点、深度 24，文字和属性受校验预算约束。浏览器原生同步、自定义存储同步、导航 ZIP、工具条目数量及隐私数据边界保持原范围。

实现入口：`app/src/components/FolioNoteEditor.jsx`、`DialogSurface.jsx`、`PersonalTools.jsx`、`app/src/lib/note-document.js`。Folio 文案来自上游 MIT 资源，英文回退位于 `src/i18n/folio.en.txt`，完整语言值在 `folio.phrases.txt`，与主目录一起由 `generate:i18n` 生成；资源生成不是应用测试。

## Folio 0.2.1 补丁

修复上游“插入块 → 文本”误报“未能完成此操作”的问题：新建块已经是普通段落，Tiptap 的 `setParagraph()` 会把无须转换返回为 `false`。Folio 先识别普通段落选区，把该情况视为成功且不重写文档，保留文字、格式、块 ID 和选区；只读或销毁后的编辑器仍拒绝执行。其他结构仍走原转换命令，未把所有失败一律视为成功。

[Folio v0.2.1](https://github.com/futelab/folio/releases/tag/v0.2.1) 已通过上游既有 [Release 门禁](https://github.com/futelab/folio/actions/runs/39566929415) 并发布 npm。加入了普通空段落、跨段落文字选区、标题转换、只读状态及“插入块 → 文本”的回归用例。Covelet 依赖及锁文件已经升级至精确版本 `0.2.1`；未运行本项目的测试、检查、构建或浏览器验收，不将上游 CI 作为本项目交互已验收的证据。

### 预览依赖缓存修正

用户随后反馈空白块选择“文本”仍报错。再次比对实际文件，安装目录的 `@futelab/folio/dist/react.js` 已包含 0.2.1 的普通段落处理，但运行中的预览使用的 `node_modules/.vite/deps/@futelab_folio_react.js` 仍声明 `0.2.0`，其文本命令仍无条件执行 `setParagraph()`。只更新 npm 包和业务界面热更新，没有刷新开发服务中已经预打包的依赖。

增加开发用 `scripts/vite-dependency-reload.mjs`，同时接入网页和 WXT 的 Vite 配置：监听根 `package.json` 与 `package-lock.json`，合并安装产生的连续写入后执行 `server.restart(true)`，重新优化依赖。插件仅在开发服务模式生效，不进入正式扩展运行时，也不影响权限、存储或用户文档。

配置更新已使既有预览自动重载。读取新生成的开发缓存源码，可以看到版本 `0.2.1` 及文本命令中的普通段落判断。本轮没有修改 Folio 上游、再次发布包、删除用户数据或屏蔽错误；没有运行测试、应用构建或浏览器交互验收，缓存源码比对不能代替空白块操作的实际验收。
