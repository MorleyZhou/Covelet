# 记录级同步合并设计

日期：2026-11-24；基于 main / a3c01c2c / 0.6.0。先读现有实现再落地本设计。

## 现状与边界

`full-data-sync.js` 已有带因果上下文的多值寄存器，但单位是 IndexedDB 存储键。导航、工具和内容偏好分别是一个大对象，因此整份选本机/云端会覆盖对象内另一侧独有的内容。本次在冲突存储键内做业务记录三方合并，不更换远程协议，不自动执行旧导航历史恢复。

权威索引仍在用户所选目录的 `all-data-v1`，内容在 `all-data-v1/blobs`；索引格式仍为 `covelet-all-data` v1。每设备使用随机 128 位 actor、递增安全整数时钟、内容 SHA-256 摘要和不可变索引名。PBKDF2-SHA256 210,000 次和 AES-256-GCM 保持原样。没有账户、服务器、遥测或广告。

## 合并单位与规则

| 类别 | 稳定身份 / 合并单位 | 规则 |
| --- | --- | --- |
| 导航网站、组件、文件夹 | `state.entries[].id` | 新增按 ID 并集；同一条的名称、网址、图标等字段三方比较。移动的 groupId/parentId/位置作为关联位置字段，冲突逐条选择，避免半次移动。文件夹保留稳定 ID，重命名不重建子项。 |
| 桌面分组、搜索引擎 | `state.groups[].id`、`state.providers[].id` | 同上；同一 ID 名称冲突逐条选择。不同 ID 不按名称或网址静默去重。 |
| 便笺、稍后读 | `notes[].id`、`reading[].id` | 不同 ID 并集；同一记录不同字段可合并，同一字段不同内容必须选择。便笺正文 body/document 是关联字段，不拼接文本。字段合并时 updatedAt/revision 取两侧有效值的最大值；时间不决定内容胜负，明确选一侧时保留该侧内容元数据。 |
| 标签 | `library.tags[].id` | 名称是可变字段；改名保留 ID，因此已有 tagIds 引用仍有效。并发同名不同 ID、悬空引用等违反领域校验时停止，保留本机，不静默丢弃。 |
| 别名、标签关联与描述 | aliases / library.items 的内容键 | 每个内容键独立合并；字段遵循三方规则，列表字段作为完整字段选择。 |
| 收藏视图 | `library.views[].id` | 按 ID 合并；筛选条件作为字段比较。 |
| 外观 | `state.settings` 的单项设置 | 不同字段合并；同字段冲突选择。背景对象作为一个字段，避免混合不匹配的资源与种类。 |
| 回收站、已有历史 | 各自记录 ID；旧导航 snapshots 作为只读集合值 | 保留已有数据和验证规则，不新增历史恢复入口。无法安全拆分的字段按单个字段显示选择。 |
| 图片、其他命名空间 | 现有 namespace/key | 保持原有完整值冲突选择，Blob 字节仍按摘要验证，不用 JSON 相等代替字节相等。 |

三方规则：两边相同则采用；一边相对共同基线没改则采用另一边；两边均改了不同字段可组合；同字段均改且不同则需选择。删除与未改采用删除；删除与修改默认保留修改，并明确显示“一边删了”，允许用户改选删除。新增的独有 ID 默认保留。没有可信共同基线时，缺少一条仅视作未知，默认保留存在的一条，同 ID 不同内容进入选择。

不按墙上时间决定胜负：因果先后由现有 operation.context 与 actor 时钟判断；并发记录按稳定身份排序，设备 ID 仅用于稳定显示顺序。应用合并后，以当前设备新时钟、观察到的全部版本为上下文，生成一个新的现有 v1 快照，保留未选择存储键和独有记录。新索引追加，不用整份覆盖/清理其他设备索引作为合并行为。

## 基线、预览与原子提交

成功同步后在本机同步元数据中保存 `mergeBase`（摘要与加密块引用）和 `mergeFrontier`（该次快照所观察到的各设备时钟），不进入可同步内容。冲突时保留这个基线，不能把最新本机分支误当共同祖先。仅当每一个竞争操作的因果上下文均覆盖整个 `mergeFrontier` 时，才可使用本机缓存基线；本机曾成功应用过某一侧，并不能证明另一侧也见过这个快照。

缓存不可用或 0.6.0 升级尚无缓存时，从竞争操作计算每个 actor 的共同已观察时钟，在现有不可变 v1 索引中读取对应的精确版本，校验索引和内容块，再物化共同祖先。某个所需版本缺失，或祖先本身在这个存储键存在未决冲突，则判定基线未知。基线未知使用保守无基线合并，不从缺失推断删除；下一次成功提交再建立本机基线。旧备份、远端索引与内容块的读取格式不变。

默认冲突操作是“预览合并”。在任何写入前解密并校验所有候选，按记录列出“两侧都改了 / 仅一边改了 / 一边删了”，展示两侧内容，允许每条选本机/云端，对可组合字段默认提供合并结果。一次应用所有选择。

预览绑定本机快照 token、同步目标、全部设备文档的因果摘要、索引文件名集合、Git 存储代际和十分钟有效期；应用重新读取远程索引并比较，任一变化要求重新预览。本机 CAS 比较覆盖内容及 Blob 字节。提交前准备完整恢复前副本，副本、合并内容和新同步状态在同一 IndexedDB commit 中加密落盘；失败则均不生效。恢复副本仅保存在本机，记录应用后的快照 token。撤销要求本机内容仍等于应用后的快照、云端因果状态未继续变化，再以 CAS 写入恢复前副本并生成新操作；不回退设备时钟或远程索引，也不覆盖合并之后的新编辑。用户继续修改后，需重新预览处理，不能用旧撤销覆盖新内容。

保持 sync-data-rules.js 的本机排除项：设备密钥、隐藏密码、云访问凭据、语言、连接与会话状态等绝不进入同步。搜索框引擎选择另存本机加密偏好，跨刷新保存，不扩大同步内容。

## 容量与失败行为

继续使用 ≤256 KiB 明文块分别加密、128 MiB 总量、≤2,000 块、≤12,000 记录、≤100 设备、≤2,000 索引。业务拆分后的预览记录也受 12,000 上限约束；合并后的领域限制仍校验。超限、缺块、哈希/解密失败、重复身份、结构无效、非法移动、并发更新均明确停止并保留本机，不能截断列表或过滤记录后报告成功。

## 验证

新增 src/lib/*.test.js 覆盖两侧独有新增、同记录不同字段、同字段冲突、删除/修改、标签改名、文件夹移动，以及无基线兼容、缓存因果前沿不匹配、不可变祖先索引回退、失效预览、CAS、恢复副本、容量失败。运行 npm test、npm run build:unpacked、npm run check:extension。

按用户后续调整，真实双浏览器验收使用 R2，替代最初要求的 WebDAV：Chrome/Edge 使用隔离配置加载实际 unpacked 扩展，连接同一 R2 存储桶目录，同步共同数据后离线分别修改同一便笺与同批导航、各新增独有记录，预览后应用再双向同步，检查两侧一致与独有记录保留。WebDAV 支持及相关回归测试继续保留。实际步骤、环境、结果与未完成边界写入 docs/verification，明确区分真实 Chrome/Edge + R2、WebDAV 模拟传输和纯逻辑测试，不把测试夹具视作真实服务验收。
