# OwnTab 扩展框架选型

调研和迁移日期：2026-10-19。

结论：采用 **WXT 0.21.4** 管理扩展入口、Manifest 和生产构建，继续使用 React 19.2.0、Vite 6.4.2 与现有 React 插件。普通网页预览和 Sites 交付仍使用原有 Vite 脚手架。此选择基于当前工程的迁移成本与维护方式，不代表已经证明 WXT 的运行性能或商店审核结果优于 Plasmo。

## 为什么选 WXT

| 比较项 | WXT | Plasmo | OwnTab 的判断 |
| --- | --- | --- | --- |
| 当前核实版本 | 0.21.4 | 0.90.5 | 版本来自当日 npm registry 查询，升级时重新核实 |
| 构建链 | Vite；0.21.4 接受 `^6.3.4`、`^7`、`^8` 的 Vite peer | CLI 0.90.5 使用 Parcel 2.9.3 及其扩展配置 | WXT 可继续使用已有 Vite 6.4.2 |
| React | 官方 React 模块，或直接使用 `@vitejs/plugin-react` | 优先支持 React/TypeScript，页面导出组件即可 | 两者均可用；当前项目直接复用现有插件 |
| 新标签页 | `entrypoints/newtab/index.html`，生成 `newtab.html` | `newtab.tsx` 或 `newtab/index.tsx` | WXT 的 HTML 入口复用 `src/main.jsx`，无需重写 UI |
| Manifest | 配置和文件入口共同生成 | `package.json.manifest` 覆盖自动生成结果 | 两者均须审查最终产物权限和 CSP |
| 浏览器目标 | CLI 可选择浏览器和 MV2/MV3 | CLI `--target` 指定浏览器与 Manifest 组合 | 本项目目前明确限制为 Chrome MV3；不能据此宣称 Firefox 已适配 |
| 存储工具 | 可选 wrapper，支持存储区前缀和版本迁移 | 可选 `@plasmohq/storage`，默认 sync，并支持网页回退 | 保留当前直接调用 Chrome API 的同步、快照和备份实现 |
| 网页预览 | 与普通 Vite 配置并存 | 可以额外保留 Vite，但同时维护 Parcel | WXT 更符合现有网页预览与扩展双入口 |

WXT 的存储工具不是跨设备冲突处理或配额处理方案。框架迁移不替换 OwnTab 已有的数据键名、schema、原生同步逻辑、图片缓存、历史快照或备份格式。

## 本次最小迁移

- 固定新增开发依赖 `wxt: "0.21.4"`，Node.js 要求为 `>=22`；沿用现有 React 和 Vite 版本。
- 新增 [扩展入口](../app/entrypoints/newtab/index.html)，复用 `src/main.jsx`。原 `app/index.html` 继续服务普通网页预览。
- 新增 [WXT 配置](../app/wxt.config.ts)。关闭自动导入，限定 Chrome 和 Manifest V3，生产包不添加后台脚本、内容脚本、弹窗、分析统计或自动发布配置。
- 将原 `public/manifest.json` 移至 [唯一 Manifest 基线](../app/extension.manifest.json)。WXT 配置读取该基线；生产 checker 对最终 Manifest 做完整结构比对，避免文件复制覆盖生成结果。
- `chrome_url_overrides.newtab` 从 `index.html` 改为 `newtab.html`。权限、host 权限、逐站点 optional host 权限和 CSP 保持原值。
- 原 `dev`、`build`、`preview`、`test` 和 `test:sites` 命令继续保留；新增 `dev:extension`。原 `.openai/hosting.json`、Worker、Sites 构建脚本与其测试不变。
- Bing 的网页开发代理仅用于普通网页预览；WXT 的真实扩展开发环境根据 `chrome.runtime.id` 直接访问已授权的 Bing origin，避免误走 `/__bing`。

## 命令与产物

在 `app/` 目录执行：

| 命令 | 作用 | 输出 |
| --- | --- | --- |
| `npm run dev` | 普通网页预览 | 原 Vite 开发服务器 |
| `npm run dev:extension` | WXT 扩展开发 | `dist/extension-dev/`；不自动打开浏览器 |
| `npm run build:extension` | Chrome MV3 生产构建、静态检查、ZIP 打包 | `dist/extension/`、`dist/owntab-0.1.0.zip` |
| `npm run check:extension` | 检查已构建的生产扩展 | 终端检查结果 |
| `npm run build` | 原 Sites 交付构建 | 原 `dist/client/`、`dist/server/`、`dist/.openai/` |

未安装 WXT 可选的 `web-ext` 浏览器启动依赖，并在配置中设置 `webExt.enabled: false`。开发目录与生产目录分开；执行开发命令不会替代生产 ZIP。

WXT 开发模式会为热更新加入本地开发服务器连接、重载后台脚本和开发 Manifest 字段。这些仅存在于 `dist/extension-dev/`；严格发布校验面向 `dist/extension/`，开发目录不能作为发布包。

## 构建与校验边界

已核对 WXT 0.21.4 的实际构建代码：生产构建清理的是解析后的目标 `dist/extension/`。调用前检查 app 的绝对路径、`dist/`、`dist/extension/`、`.wxt/`，拒绝符号链接或非目录目标。保留 `dist/client/` 等其他产物。

WXT 会将 HTML 入口移到扩展根目录，生成 `/chunks/...` 和 `/assets/...` 形式的扩展根路径。checker 将单个 `/` 开头的资源解析到包内根目录，并要求对应真实文件仍在 `dist/extension/` 内；继续拒绝协议 URL、`//`、反斜杠、越界路径、缺失资源和额外能力。

静态检查继续覆盖 Manifest 能力清单、CSP、打包资源、常见远程代码与网络 API 模式，以及已审查的搜索、Bing 和网站信息获取桥接。生产 Manifest 除新标签页文件名外与迁移前一致。构建与 checker 已通过；此文档不把这些结果等同于真实 Chrome/Edge 安装、跨设备同步、性能测试或商店审核通过。
