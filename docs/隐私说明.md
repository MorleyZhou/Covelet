# Covelet 隐私说明 / Privacy policy

更新日期为 2026-11-25。本文适用于 **0.3.1 至 0.7.0**；按版本标注的历史段落描述该次发布行为，0.7.0 的新增范围见下文。公开托管版本与商店状态分别见[托管隐私政策](https://covelet.future-element.com/privacy/)和[发布状态](store/发布状态.md)；修改本文件不表示已部署公开页面。

发布者：Morley。支持／隐私联系：support@morley.work。

Covelet 提供新标签页导航、搜索、布局与外观、便笺、本机文章阅读、RSS 收件箱、用户主动保存的本机会话、GitHub 贡献组件和可选自备存储同步。没有 Covelet 账号、广告、遥测、自动日志上传或 Covelet 数据服务器。旧工具包和旧标签集合的捕获／恢复入口仍已移除；0.7.0 的本机会话使用独立的新数据集合。不提供浏览器阅读清单导入，不被动收集浏览历史。

导航、网址、便笺及其历史、稍后读、图片、外观、隐私标记和组件记录保存在当前浏览器的加密 IndexedDB 中。正文／高亮缓存、RSS 和本机会话也使用设备密钥加密存储，但明确排除同步及现有完整备份。设备 AES-GCM 密钥不可导出，但同源应用可使用它；这不能替代设备锁屏或防止已获浏览器配置访问能力者读取内容。隐藏密码控制本机显示，与设备加密密钥及同步密码不同。旧版功能记录可能保留在本机数据、备份或同步副本中，不会恢复已移除的功能入口。

浏览器原生配置同步已停用，不使用 storage.sync 发送新数据；旧浏览器云端副本不会因此自动删除。「自备存储同步」默认关闭，用户配置并解锁后，以同步密码加密内容和图片，直接发送至其选择的 R2、OSS、GitHub、GitLab 或 HTTPS WebDAV。服务商接收加密内容、目标路径、请求时间和网络元数据，并按其规则处理。设备密钥、隐藏密码和当前隐藏状态不随内容同步。连接凭据用于向所选服务认证，使用同步密码加密后保存在本机，不进入备份或同步内容。同步密码及解密后的凭据只在 chrome.storage.session 中使用，锁定或重启后用同步密码解锁。自动同步需要单独开启。其他设备、并发版本、恢复点和备份可能保留旧内容，删除本机内容不代表删除所有副本。

全局或任一桌面使用「随机壁纸」时，扩展访问所选来源。Bing 使用 https://www.bing.com；Wikimedia Commons 按需授权 https://commons.wikimedia.org 以读取图片及授权信息，并授权 https://upload.wikimedia.org 以下载图片。所选来源接收 IP 等连接信息，请求省略 Cookie 和 referrer，图片缓存在本机。各桌面共用本设备的来源、轮换间隔和当前图片，切屏只读缓存；全局和所有桌面均不再使用随机壁纸后，停止后续壁纸请求。只将当前桌面改为颜色背景不会停止其他桌面的共享轮换。搜索由浏览器默认搜索 API 或用户选定搜索引擎处理，查询由对应服务接收，Covelet 不收集查询。

网站信息和图片获取在用户添加／编辑、点击获取或确认导入／修复时进行。仅按需申请实际网站／图片来源的访问权限，不扫描浏览历史；普通导航显示、刷新和文件夹浏览使用本机图片缓存。被请求的站点接收所需地址及连接元数据。工具栏由用户点击触发 activeTab，读取被调用页面的地址、标题和图标声明；用户明确选择便笺或读取选文时，另读取主框架选中文字和出处，保存前可修改或取消。这条工具栏读取路径不遍历其他标签；0.7.0 的窗口会话读取须另行授予可选 tabs 权限并主动预览保存。用户在便笺中插入远程图片时，显示图片可能连接图片来源。

GitHub 贡献组件在用户授权 github.com 并配置账号后，读取该账号的公开贡献日历。组件在加载、恢复可见和定期刷新时检查本机缓存，需要更新时连接 GitHub，也可手动刷新。不读取私有仓库或登录令牌。GitHub 接收用户名及连接元数据。首页时间和日期使用设备时间，所选时区、农历和星座均在当前浏览器中计算。时区和显示偏好保存在本机。此功能不请求定位或网络校时。独立时钟和倒计时组件已移除，当前版本不发送通知。

用户可编辑／删除内容、禁用同步、选择背景、撤销网站访问权限并导出备份。卸载前请保存所需内容。反馈仅由用户主动发送，不自动附带日志、网址、图片或备份。不出售数据，不用于广告、画像、无关分析或信用决定；数据使用限于已披露功能，并遵守 Chrome Web Store User Data Policy（包括 Limited Use）。公开政策网址为 https://covelet.future-element.com/privacy/。

### 0.4.0 桌面与书签

桌面名称和顺序属于导航数据，可随自备存储同步。默认桌面和首次引导偏好保存在本机，浏览器负责管理用户绑定的扩展快捷键。Covelet 内容搜索在本机运行。确认批量打开网站时，浏览器会访问所选链接。

用户选取的 Markdown 链接文件在本机解析。书签 HTML 导出在本机生成，包含所选导航的名称、网址和分组，排除标记为隐藏的内容。书签 HTML 和普通完整备份未加密，完整备份可能包含私密内容。

### 0.5.0 内容整理与密码备份

备注、跨内容标签、动态清单、阅读日期、关键词和导航回收记录沿用本机加密存储及可选完整数据同步。回收站默认可恢复 30 天，到期内容在后续确认写入时清理；图片仍可能因历史快照、恢复点或其他备份被保留。

用户明确选择网页选文便笺或点击读取时，使用既有 activeTab / scripting 读取当前页主框架选中文字、标题和来源网址，不读取其他标签或框架全文。文字保存为普通便笺，不执行其中的 HTML。Markdown 便笺导入在本机解析，将图片保留为文字或链接，不因预览下载图片；Markdown 导出排除标记隐藏的便笺。

独立备份密码仅用于当前导出或解锁，不替代设备隐藏密码或同步密码，也不写入设置、同步内容、日志或备份。全部加解密和校验在当前浏览器执行，不向 Covelet 服务器传输文件。旧明文 JSON/ZIP 继续支持；加密文件的参数与大小限制见 [格式说明](development/password-backup-v1.md)。本地候选的政策说明不表示已经更新公开托管页面或通过商店审核。

### 历史：0.6.0 查找、引用与文件交换

本节记录 0.6.0 发布时的行为；0.7.0 新增的浏览器来源、持久阅读批注等范围见下一节。

命令面板和结构化内容搜索均在本机运行。便笺命中定位词和高亮只用于当前页面，不进入同步或备份。指定便笺和动态清单的桌面引用、每个桌面的独立外观及清单条件沿用本机加密存储、完整备份和已开启的内容同步，不新增权限、外部服务或后台扫描。网页选文可经预览和确认追加到已有便笺，保留原文及来源标题、网址；既有主框架选文读取范围不变。

Raindrop HTML、OneTab 文本和 Markdown 文件在本机解析，不因解析访问来源账号、执行 HTML 或下载附件；明确确认的图标获取仍遵循逐来源授权。重复项只在用户选定来源、目标和字段后合并支持的标签或追加备注。Markdown 资料库 ZIP 是未加密交换文件，包含所选网站、稍后读和便笺及可表达的元信息，始终排除标记隐藏的内容及私密文件夹内的内容，即使当前已解锁。该排除规则不同于可能包含私密内容的完整备份；后者仍可选择独立密码加密。

### 0.7.0 阅读、浏览器入口、同步与备份

添加稍后读链接或更换网址成功后，仅在已有精确来源授权时尝试获取该网页原文；也可明确点击提取／重试。请求省略 Cookie 和 Referer、拒绝重定向，并限制时间和大小。不执行网页脚本或使用远程解析服务，失败仍保留原链接。已经保存的正文可在本机阅读、全文匹配和添加高亮备注；阅读器的图片没有自动远程加载，仅在用户点击单张图片并授权其来源后读取、校验为栅格图片并通过本机 Blob 显示。正文、高亮和阅读样式仅本机保存，不进入同步或现有完整备份；公开阅读条目可另行导出为未加密 Markdown，隐藏条目始终排除。

RSS 默认关闭。用户主动添加并授权 RSS/Atom 来源后，浏览器运行期间按订阅周期请求该来源，服务端会收到所请求地址和连接元数据。只保留有界的纯文本标题、摘要和链接；刷新不自动抓取文章正文或图片。订阅与收件箱加密保存在本机，不同步或纳入完整备份；收件箱滚动保留每源最多 100 条、总共 500 条。浏览器关闭时不运行，启动后恢复计划。

命令面板的浏览器来源按明确授权读取标签、历史或书签元数据，结果仅在打开的面板中短暂使用，不建立持久索引。用户确认保存的本机会话只含普通 HTTP(S) 标签的名称、网址和固定状态，不含正文、Cookie、表单、截图、凭据或浏览器标签 ID；排除隐私窗口、内部页面和不支持的 URL。保存不会关闭原标签；恢复先预览并确认，每批最多打开 10 个后台标签，重复链接跳过，取消停止后续创建。会话仅保存在本机，不随同步或现有完整备份外发。

同步冲突先按记录预览，两侧修改、单侧修改和删除可逐条选择；应用前保留恢复前副本，并可撤销上次合并。合并不关闭本机隐藏状态。修改同步密码前校验保留的云端数据，再以新密码重加密并切换当前权威世代；完成后须显式输入新密码解锁。旧密码不能读取当前新世代，但旧云端归档、Git 历史或已下载副本不能追溯撤销，换密不等于远程擦除。

便笺修改前的历史快照有数量和字节上限，最多 20 版；可比较并恢复，恢复前的当前版本会保存为历史。历史随便笺内容同步并进入新版完整备份；完整加密备份默认包含隐藏便笺及其历史，仍不包含访问凭据、隐藏密码、设备密钥或语言偏好。新版读取器继续支持旧 0.6.0 备份，外层 `.covelet` 格式保持兼容。

支持所选目录文件访问的浏览器可配置每日／每周定时加密备份，默认包含完整备份范围内的隐藏内容，管理最近三份自有 `.covelet` 文件。设置时派生并在本机专用 IndexedDB 保存不可导出的加密密钥、盐和目录句柄，不保存原始备份密码；这些数据不进入同步或备份。禁用计划会移除本机密钥和句柄，已有文件保留。后台不发起目录选择或授权弹窗，权限失效会停止并提示重新授权；不能保证浏览器关闭或系统休眠期间执行。Firefox 当前不支持该外部目录能力，仍可手动导出和恢复加密备份。

## English

Updated November 25, 2026. Applies to Covelet **0.3.1–0.7.0**. Version-labelled historical sections describe those releases. Morley publishes Covelet. Contact support@morley.work for support or privacy inquiries. See the [hosted policy](https://covelet.future-element.com/privacy/) and [release status](store/发布状态.md). Editing this file does not deploy the public page.

Covelet provides new-tab navigation, search, appearance, notes, local article reading, an RSS inbox, explicitly saved local browser sessions, public GitHub contributions and optional storage sync. No Covelet account, advertising, telemetry, automatic log upload or Covelet data server is included. Retired tool packs and old tab-record capture/restore remain unavailable; 0.7.0 local sessions use a separate collection. Browser Reading List import and passive browsing-history collection are not provided.

Content, note history, images and settings are stored in encrypted IndexedDB in the current browser. Article/highlight caches, RSS and local browser sessions also use device-key encryption, but are explicitly excluded from sync and existing complete backups. The non-extractable device key can still be used by same-origin application code; encryption is not a substitute for device security. The hiding password controls local display and is separate from device encryption and the sync password. Records from retired features may remain in local data, backups or synced copies without restoring those features.

Browser-native sync is disabled; this does not automatically delete old browser-cloud copies. Bring-your-own storage sync is off by default. After configuration and unlock, it encrypts content and images with the user's sync password and connects directly to user-selected R2, OSS, GitHub, GitLab or HTTPS WebDAV. Providers receive ciphertext, paths, request times and network metadata. Device keys, hiding passwords and the current hiding state are excluded from synced content. Connection credentials authenticate requests to the selected service and are not included in backups or synced content. Connection credentials are encrypted with the sync password and saved on this device. The password and decrypted credentials are held in chrome.storage.session. After locking sync or restarting the browser, enter the sync password to unlock the connection. Automatic sync requires a separate opt-in.

Random Wallpaper contacts the selected source when the global background or any desktop uses it. Bing uses www.bing.com. Wikimedia Commons requests optional access to commons.wikimedia.org for image and license metadata, and upload.wikimedia.org for image downloads. The selected hosts receive connection metadata. Requests omit cookies and referrers, and images are cached locally. Desktops share this device's source, rotation interval and current image; switching desktops only reads the cache. Further wallpaper requests stop when neither the global background nor any desktop uses Random Wallpaper. Changing only the current desktop to a color background does not stop shared rotation for other desktops. Searches go to the browser's default or explicitly selected search provider, which receives the query; Covelet does not collect it. Website/icon acquisition and confirmed import/repair may contact the selected origins after origin-specific grants; ordinary navigation icon rendering uses local cached bytes. Clicking the toolbar provides temporary activeTab access to that page's URL, title and icon declarations through a packaged script. Fields can be edited and saving can be canceled. This toolbar path does not enumerate other tabs; 0.7.0 window-session capture separately requires optional tabs access and explicit preview/confirmation. Loading user-inserted remote note images may contact their hosts.

After authorization and account configuration, GitHub widgets read that account's public contribution calendar. They check the local cache when loaded, when becoming visible and during periodic refresh, and contact GitHub when an update is needed. Manual refresh is also available. No private repositories or login tokens are read. GitHub receives the username and connection metadata. The home page uses the device clock and computes the selected time zone, lunar date and zodiac sign in the browser. Time zone and display preferences stay on this device. The feature makes no location or network time requests. Standalone clock and countdown widgets have been removed; the current version does not send notifications.

Required permissions are storage, search, activeTab, scripting and alarms, with favicon on Chrome/Edge and the fixed Bing host. Firefox does not declare the unavailable favicon interface. Storage supports migration and session credentials; content and settings use encrypted IndexedDB. Search follows the browser's default search settings. ActiveTab and scripting read the invoked page's information after a toolbar click. Alarms support background sync, user-configured RSS updates, supported scheduled backups and legacy clock cleanup. The named permissions tabs, history and bookmarks are optional, requested only from dedicated user-activated authorization controls. Opening the panel, typing a query or background operation does not request them. Browser sources and local sessions are not read or shown in hidden mode. Optional HTTP(S) host ranges support exact-origin grants for selected websites, articles, images, RSS feeds, Wikimedia Commons, GitHub and storage providers; they do not grant blanket access at installation. No geolocation or notification permission is requested. Bookmark HTML file import does not need bookmark-library permission.

User-selected bookmark HTML is parsed locally. Complete backups, navigation ZIPs, notes/Read Later exports and recovery points have different scopes. Ordinary JSON/ZIP backups are unencrypted and may contain private URLs, text and images, including marked or currently hidden content; do not share them publicly. Starting with 0.5.0, complete backups may instead use an independent password to create an encrypted .covelet file. This password is not saved and cannot be recovered if lost. Credentials, sync connections and passwords are excluded from complete backups. Encryption, decryption and validation run locally. Restoration validates the content, requires confirmation and keeps a pre-restore copy. Legacy tab records can be retained or exported but cannot open tabs or be restored separately. Other devices, conflicts, recovery points and backups may retain older copies. Local deletion is not deletion everywhere. Users can edit/delete content, disable sync, change backgrounds, revoke website access and export data before uninstalling. Feedback is voluntary with no automatic attachments. Data is not sold or used for advertising, profiling, unrelated analytics or credit decisions. Use is limited to disclosed features and follows the Chrome Web Store User Data Policy, including Limited Use. The hosted policy URL is https://covelet.future-element.com/privacy/.

### Desktops and bookmarks in 0.4.0

Desktop names and order are navigation data and can sync with your own storage. Your default desktop and first-run preference stay on this device. Your browser manages any extension keyboard shortcut you assign. Searches across Covelet content run on your device. When you confirm opening a group of sites, the browser visits the selected links.

Markdown link files you select are parsed locally. Bookmark HTML exports are created on your device and include names, URLs and groups for the selected shortcuts. Content marked as hidden is excluded. Bookmark HTML exports are unencrypted. Complete backups can include private content and may use an independent password for encryption from 0.5.0 onward.

### Historical: search, references and file exchange in 0.6.0

This section records the 0.6.0 release. Browser sources and persistent reading annotations added in 0.7.0 are described below.

The command panel and structured content search run locally. Note match terms and highlights are temporary page state, excluded from backups and sync. Pinned note and saved-view references, per-desktop appearance and saved filters use the existing encrypted local storage, complete backups and content sync when enabled. They add no permissions, external services or background scans. After preview and confirmation, selected main-frame text can be appended to an existing note with its source title and URL, without reading full pages or other tabs.

Raindrop HTML, OneTab text and Markdown files are parsed locally without accessing source accounts, executing HTML or downloading attachments during parsing. Explicit icon acquisition remains subject to per-origin grants. Duplicate imports merge supported tags or append descriptions only after the user chooses targets, sources and fields. Markdown library ZIPs are unencrypted exchange files containing selected sites, Read Later items, notes and supported metadata. They always exclude marked private content and content inside private folders, even while unlocked. Complete backups have a different scope, may include private content, and can use independent password encryption.

### Reading, browser sources, sync and backups in 0.7.0

After successfully saving a new Read Later URL or changing it, Covelet attempts to fetch that article only with an existing exact-origin grant. Extraction/retry is also an explicit action. Requests omit cookies and referrers, reject redirects and have time/size limits. No page scripts or remote parsing service are used; failure keeps the link. Saved articles support local reading, full-text matching, highlights and notes. Reader images have no automatic remote source: each image is fetched only after an explicit click and an origin grant, validated as a raster and displayed through a local Blob URL. Article content, annotations and reading styles stay on this device, outside sync and existing complete backups. Public reading items can be exported separately as unencrypted Markdown; marked private items are always excluded.

RSS is off by default. After you add and authorize an RSS/Atom source, the running browser periodically requests that source, which receives the requested address and connection metadata. The inbox stores bounded plain-text titles, summaries and links. Refreshing a feed does not fetch article bodies or images. Feeds and the inbox are encrypted locally, excluded from sync and complete backups, and retain up to 100 entries per source and 500 overall on a rolling basis. No task runs while the browser is closed; startup restores its schedule.

Browser-source search reads tab, history or bookmark metadata after the relevant optional grant. Results are transient panel state, without a persistent index. Sessions you explicitly confirm contain ordinary HTTP(S) tab titles, URLs and pinned flags, without page content, cookies, forms, screenshots, credentials or browser tab IDs. Private windows, internal pages and unsupported URLs are excluded. Saving leaves original tabs open. Restoration requires preview and confirmation, opens at most ten inactive tabs per batch, skips duplicate URLs and stops further creation on cancellation. Sessions stay on this device, outside sync and existing complete backups.

Sync conflicts have per-record previews and choices for changes and deletions. A pre-merge copy is kept, and the last merge can be undone. Merging does not disable local hidden mode. Password rotation validates retained remote content before re-encryption and cutover to the new authoritative generation, followed by explicit unlock with the new password. Old passwords cannot read that new generation, but old cloud archives, Git history and downloaded copies cannot be retroactively revoked; rotation is not remote erasure.

Note history keeps bounded pre-edit snapshots, up to twenty versions, with comparison and restoration. The current version is captured before restoring an older one. History follows note sync and the new complete backup format. Encrypted complete backups include hidden notes and their history by default, while excluding access credentials, hiding passwords, device keys and language preferences. The new reader still accepts old 0.6.0 backups and retains the existing outer .covelet format.

Browsers supporting writable selected directories can schedule daily/weekly encrypted backups, including hidden content within the complete-backup scope, and manage the latest three owned .covelet files. Setup derives and saves a non-extractable encryption key, salt and directory handle in a dedicated local IndexedDB; the original backup password is not saved. These capabilities are excluded from sync and backups. Disabling the schedule removes the local key/handle and preserves existing files. Background tasks never open a directory picker or permission prompt. Lost access stops the operation with a reauthorization message. Execution while the browser is closed or the system sleeps is not guaranteed. Firefox currently lacks this external-directory capability; manual encrypted export and recovery remain available.
