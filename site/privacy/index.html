隐私政策

更新于 2026 年 11 月 25 日 · 适用于 Covelet 0.3.1 至 0.7.0

发布者为 Morley。支持和隐私联系邮箱为 support@morley.work。

本机数据

网站、文件夹、便笺及其历史、稍后读、图片、外观和隐私标记保存在当前浏览器的加密 IndexedDB 中。0.7.0 的文章正文与高亮、RSS 和本机会话也使用设备密钥加密保存，但不进入同步或现有完整备份。扩展可使用不可导出的设备密钥，设备访问权限仍由你的设备保护。隐藏密码用于控制本机显示，与设备密钥和同步密码分开。退役功能的记录可能仍留在本机数据、同步副本或备份中，不恢复旧标签集合的捕获或恢复入口。

首页时间使用设备时钟。时区、农历和星座在当前浏览器中计算，显示偏好保存在本机。首页时间无需定位或联网校时。

从 0.4.0 起，桌面名称和顺序属于导航数据，可随自备存储同步。默认桌面和首次引导偏好保存在本机。浏览器负责管理你绑定的扩展快捷键。

0.6.0 发布时，全局命令面板和带标签、类型等条件的内容搜索在本机读取已有资料。搜索结果、正文命中高亮和定位是临时派生状态，不进入备份或同步；主动保存为动态清单的筛选条件属于内容配置。固定便笺和动态清单的组件保存目标引用，按原资料及其隐私标记显示；引用和每个桌面的外观设置沿用现有加密存储、完整备份和可选自备存储同步。这些 0.6.0 功能不新增安装权限、外部服务或后台扫描，也不读取浏览历史或其他标签页。0.7.0 新增的可选浏览器来源和持久阅读批注另见下文。

0.7.0 的命令面板可在分别授权后搜索普通标签、浏览器历史或书签。结果只在打开的面板中短暂使用，不保存副本或建立索引。用户主动预览并确认保存的本机会话只含普通 HTTP(S) 标签的标题、网址和固定状态，不含正文、Cookie、表单、截图、凭据或浏览器标签 ID；排除隐私窗口、内部页面和不支持的网址。保存不会关闭原标签；恢复先确认，每批最多新建 10 个后台标签并跳过已打开网址，取消停止后续创建。隐藏模式下不读取或展示这些浏览器来源和本机会话，也不展示其数量。

自备存储同步

同步默认关闭。配置并解锁后，Covelet 使用同步密码加密内容和图片，再直接发送到你选择的 R2、OSS、GitHub、GitLab 或 HTTPS WebDAV。服务商会接收加密内容、文件路径、请求时间和网络连接信息。自动同步需单独开启。

连接凭据使用同步密码加密后保存在本机。同步密码和解密后的凭据仅在解锁期间保存在浏览器会话中。设备密钥、隐藏密码、当前隐藏状态和连接凭据不随内容同步。浏览器原生同步已停用。旧云端副本、其他设备、恢复点和备份可能仍保有早期数据。

同步冲突按记录提供预览和逐条选择，应用前保留恢复前副本，可撤销上次合并，不关闭本机隐藏状态。修改同步密码前验证保留的云端内容，再以新密码重加密并切换当前权威版本；完成后需要显式输入新密码解锁。旧密码不能读取新的当前版本，但换密不能追溯撤销旧云端归档、Git 历史或已下载文件，也不替换第三方服务的访问凭据。语言偏好、搜索引擎的本机选择、正文／高亮缓存、RSS 和本机会话不参与同步。

何时会联网

  • Covelet 内容搜索在本机运行。提交网页搜索时，查询会交给浏览器默认搜索服务或你选择的搜索引擎。打开网站或确认批量打开时，浏览器会访问所选链接。
  • 全局或任一桌面使用随机壁纸时，Bing 来源连接 www.bing.com；Wikimedia Commons 按需授权 commons.wikimedia.org 获取图片及许可信息，并授权 upload.wikimedia.org 下载图片。来源会收到连接信息。请求不带 Cookie 或 Referer，图片缓存在本机。各桌面共用当前设备的壁纸来源、轮换间隔和当前图片，切换桌面本身只读取缓存。全局和所有桌面均不再使用随机壁纸后，停止后续壁纸请求；仅将当前桌面改为颜色背景不会停止其他桌面的共享轮换。
  • 添加或编辑网站时，主动获取网站信息或图片，以及确认导入或修复图片时，可能连接相关站点。Covelet 仅按需申请实际来源的访问权限，日常导航使用本机缓存。显示便笺中的远程图片时，也可能连接图片来源。
  • 成功添加稍后读链接或更换网址后，仅在已授予精确来源权限时尝试读取原文，也可明确点击提取或重试。请求省略 Cookie 和 Referer、拒绝重定向，并设时间和大小上限；不执行网页脚本、不使用远程解析服务。失败保留链接。已保存正文在本机阅读与搜索，阅读器图片仅在逐张点击并授权后加载为经过校验的本机 Blob，不自动读取远程图片。
  • RSS 默认关闭。你添加并授权 RSS/Atom 来源后，浏览器运行期间按订阅周期只请求已添加的来源；对方会收到订阅地址及连接信息。收件箱只存有界纯文本标题、摘要、链接和日期，不因刷新抓取文章正文或图片。浏览器关闭时不运行，启动后恢复计划。
  • 配置并授权 GitHub 贡献组件后，组件可按需请求所选账号的公开贡献日历。GitHub 会收到用户名和连接信息。组件只读取公开贡献数据。

扩展权限

  • storage 用于迁移旧数据并保存会话连接信息。内容和设置使用加密 IndexedDB。
  • search 用于调用浏览器默认搜索服务。
  • Chrome/Edge 的 favicon 用于主动添加或导入时读取浏览器已有图标。Firefox 不声明此不可用接口，可使用现有本机、字母或明确授权获取的图标。
  • activeTab 和 scripting 用于点击工具栏后读取当前页的地址、标题和图标声明。明确选择网页选文便笺或点击读取时，另读取主框架选中文字、标题和来源网址，不读取其他标签或框架全文。你可以保存为新便笺，或追加到明确选定的已有便笺；保存前可修改或取消。
  • alarms 用于接续后台同步、用户配置的 RSS 更新、支持的定时备份及清理旧版时钟提醒。
  • 可选 tabs 用于按标题和网址搜索普通标签、切换或关闭选中标签，以及预览保存窗口链接和核对恢复重复项。
  • 可选 history 和 bookmarks 分别用于按输入词读取已有历史和搜索浏览器书签；不修改书签库，不持久保存或同步搜索结果。
  • www.bing.com 是固定壁纸来源。可选 HTTP(S) 权限仅用于逐来源授权，安装时不会授予所有网站的访问权限。

上述三个可选权限只在专用授权按钮的用户操作中申请；安装、打开面板、输入查询和后台运行不会自动申请。拒绝或撤销授权不影响原有内容搜索。可选 HTTP(S) 来源还用于你选择的原文、图片和 RSS，不扩大安装时的固定主机范围。扩展仍不请求地理位置或通知权限。书签 HTML 文件导入无须书签库权限。

备份和数据控制

用户选择的书签 HTML、Markdown 链接、Raindrop HTML 和 OneTab 文本在本机解析，解析和预览不会访问导出来源的账号。导入支持的标签和备注会先供你审阅；重复网址默认保留本地信息，只有明确选定目标、来源和合并选项后才合并相应字段。

书签 HTML 和 Markdown 资料库 ZIP 在本机生成，生成过程不下载远程资源。书签 HTML 包含所选导航的名称、网址和分组；Markdown 资料库可包含所选网站、稍后读和便笺的正文、网址、标签、备注及其他支持的元数据，并生成索引和相对链接。这些导出未加密，始终排除标记为私密的内容（包括私密文件夹中的内容），即使当时已解锁显示。导出预览、文件名、索引和计数同样排除这些内容。

普通 JSON/ZIP 备份文件未加密，完整备份可能包含标记为私密或当前隐藏的内容，请妥善保管。从 0.5.0 起，完整备份也可用独立密码导出为 .covelet 加密文件。登录凭据、同步连接和密码不进入完整备份。备份密码不保存，丢失后无法恢复加密文件；加解密和校验均在本机进行。恢复前会校验文件并请你确认，同时在浏览器中保留一份恢复前副本。

0.7.0 的便笺历史保存有数量和字节限制的修改前快照，最多 20 版；恢复旧版前会把当前版本保留为历史。历史跟随便笺同步并进入新版完整备份，新读取器继续支持旧 0.6.0 备份。完整加密备份默认包含其范围内的隐藏内容和便笺历史，仍排除访问凭据、隐藏密码、设备密钥和语言偏好。正文／高亮缓存、阅读样式、RSS 与本机会话不在现有完整备份范围；公开阅读条目可另行导出为未加密 Markdown，隐藏内容仍被排除。

支持写入所选目录的浏览器可设置每日或每周定时加密备份，管理最近三份自有 .covelet 文件。设置时在本机专用 IndexedDB 保存不可导出的加密密钥、盐和目录句柄，不保存原始备份密码；这些能力不进入同步或备份。禁用计划移除本机密钥和句柄，已有文件保留。后台不会打开目录选择器或申请权限，目录授权失效会停止并提示重新授权；不能保证浏览器关闭或系统休眠期间执行。Firefox 当前不支持该外部目录能力，手动加密导出和恢复仍可使用。

你可以编辑或删除内容、关闭同步、选择背景、撤销网站访问权限和导出备份。反馈由你主动发送，扩展不会自动附上日志、网址、图片或备份。

扩展与官网

Covelet 扩展无需注册账号。扩展无广告、使用统计、自动日志上传或 Covelet 数据服务器。Covelet 不出售数据，也不将数据用于广告画像或信用决定。数据使用限于上文列出的功能，并遵守 Chrome Web Store User Data Policy 的 Limited Use 要求。

官网由 Cloudflare Pages 托管。首页使用 Cloudflare Web Analytics 统计网站访问。

Privacy Policy

Updated November 25, 2026 · Applies to Covelet 0.3.1–0.7.0

Morley publishes Covelet. For support or privacy inquiries, email support@morley.work.

Data on your device

Sites, folders, notes and their history, Read Later items, images, appearance preferences, and privacy markings are stored in encrypted IndexedDB in your current browser. Article/highlight caches, RSS and local sessions in 0.7.0 also use device-key encryption, but are excluded from sync and existing complete backups. The extension can use the non-extractable device key. Your device's access controls still apply. The hiding password controls local display and is separate from the device key and sync password. Records from retired features may remain in local data, synced copies, or backups without restoring old tab-record capture or restoration.

The home page uses your device clock. It computes the selected time zone, lunar date, and zodiac sign in the browser and saves the display preferences on your device. The clock needs neither location access nor an online time service.

Starting with 0.4.0, desktop names and order are part of your navigation data and can sync with your own storage. Your default desktop and first-run preference stay on this device. Your browser manages any extension keyboard shortcut you assign.

In the 0.6.0 release, the global command panel and content searches with conditions such as tags and types read existing content on your device. Search results, body-match highlights, and match positions are temporary derived state excluded from backups and sync. Filters you explicitly save as a dynamic list are content configuration. Pinned note and dynamic-list widgets store target references and display the original content under its privacy markings. References and per-desktop appearance settings use the existing encrypted storage, complete backups, and optional sync with your own storage. Those 0.6.0 features add no installation permissions, external services, or background scans, and do not read browsing history or other tabs. Optional browser sources and persistent reading annotations added in 0.7.0 are described below.

In 0.7.0, the command panel can search ordinary tabs, browsing history or bookmarks after separate optional grants. Results are transient panel state, without saved copies or an index. Sessions you explicitly preview and confirm contain ordinary HTTP(S) tab titles, URLs and pinned flags, without page content, cookies, forms, screenshots, credentials or browser tab IDs. Private windows, internal pages and unsupported URLs are excluded. Saving leaves original tabs open. Restoration requires confirmation, opens at most ten inactive tabs per batch, skips existing URLs and stops further creation when canceled. Browser sources and local sessions, including their counts, are not read or shown in hidden mode.

Sync with your own storage

Sync is off by default. When configured and unlocked, Covelet encrypts content and images with your sync password and sends them directly to your selected R2, OSS, GitHub, GitLab, or HTTPS WebDAV service. The provider receives encrypted content, file paths, request times, and network connection information. Automatic sync requires a separate opt-in.

Connection credentials are encrypted with the sync password and saved on this device. The password and decrypted credentials stay in browser session storage while sync is unlocked. Device keys, hiding passwords, the current hiding state, and connection credentials are excluded from synced content. Browser-native sync is disabled. Old cloud copies, other devices, recovery points, and backups may retain earlier data.

Sync conflicts have per-record previews and choices, with a pre-merge copy and an option to undo the last merge. Merging does not turn off local hidden mode. Password rotation validates retained cloud content before re-encryption and cutover to the new authoritative generation, followed by explicit unlock with the new password. Old passwords cannot read the new generation, but old cloud archives, Git history and downloaded files cannot be retroactively revoked. Rotation is not remote erasure and does not replace third-party service credentials. Language preferences, the local search-engine selection, article/highlight caches, RSS and local sessions are excluded from sync.

When Covelet connects to the internet

  • Search across Covelet content runs on your device. Submitting a web search sends the query to the browser's default search service or the search engine you choose. When you open sites individually or confirm opening a group, the browser visits the selected links.
  • When the global background or any desktop uses Random Wallpaper, the Bing source contacts www.bing.com. Wikimedia Commons requests optional access to commons.wikimedia.org for image and license metadata, and upload.wikimedia.org for image downloads. The selected hosts receive connection information. Requests omit cookies and referrers. Images are cached locally. Desktops share this device's wallpaper source, rotation interval, and current image; switching desktops itself only reads the cache. Further wallpaper requests stop when neither the global background nor any desktop uses Random Wallpaper. Changing only the current desktop to a color background does not stop shared rotation for other desktops.
  • Adding or editing a site, requesting site information or images, or confirming image import or repair may contact the relevant origin. Covelet requests access for each origin as needed. Everyday navigation uses the local cache. Displaying a remote image in a note may contact that image's host.
  • After a new Read Later link or changed URL is saved, Covelet attempts to fetch the original article only with an existing exact-origin grant. Extraction/retry is also an explicit action. Requests omit cookies and referrers, reject redirects and have time/size limits. No page scripts or remote parsing service are used; failure keeps the link. Saved content is read and searched locally. Reader images load only after a click on that image and an origin grant, using validated raster bytes and a local Blob URL, without automatic remote image requests.
  • RSS is off by default. After you add and authorize an RSS/Atom source, the running browser periodically requests only added sources, which receive the feed address and connection information. The inbox stores bounded plain-text titles, summaries, links and dates. Refreshing a feed does not fetch article bodies or images. Nothing runs while the browser is closed; startup restores its schedule.
  • After authorization and configuration, the GitHub contributions widget can fetch the selected account's public contribution calendar. GitHub receives the username and connection information. The widget reads public contribution data only.

Extension permissions

  • storage supports legacy data migration and session connection information. Content and settings use encrypted IndexedDB.
  • search calls the browser's default search service.
  • On Chrome/Edge, favicon reads existing browser icons during explicit add or import actions. Firefox does not declare this unavailable interface; existing local, letter or explicitly authorized site icons remain available.
  • activeTab and scripting read the current page's URL, title, and icon declarations after a toolbar click. Explicitly choosing a webpage selection note or clicking to read also reads selected text, the title, and source URL from the main frame, without reading other tabs or full frame content. You can save a new note or append to an existing note you explicitly select, and edit the information or cancel before saving.
  • alarms resumes background sync, user-configured RSS updates, supported scheduled backups and legacy clock cleanup.
  • Optional tabs access supports searching ordinary tab titles and URLs, switching or closing selected tabs, previewing window-link capture and checking duplicate URLs before restoration.
  • Optional history and bookmarks access supports querying existing history by typed text and searching bookmarks. Covelet does not modify the bookmark library or persist or sync search results.
  • www.bing.com is a fixed wallpaper host. Optional HTTP(S) access is granted per origin and does not provide access to all sites at installation.

These three optional permissions are requested only by dedicated user-activated authorization controls, not automatically during installation, panel opening, typing or background operation. Declining or revoking them does not affect existing content search. Optional HTTP(S) grants also cover articles, images and feeds you select; the fixed installation host scope is unchanged. The extension still requests neither geolocation nor notification access. Bookmark HTML file import does not require bookmark-library permission.

Backups and data controls

Bookmark HTML, Markdown link, Raindrop HTML, and OneTab text files that you choose are parsed locally. Parsing and preview do not access accounts at the export source. Supported tags and descriptions are presented for review. Duplicate URLs keep local information by default; fields are merged only after you explicitly choose the target, source entries, and merge options.

Bookmark HTML and Markdown library ZIP exports are generated on your device without downloading remote resources. Bookmark HTML includes names, URLs, and groups for the selected shortcuts. A Markdown library can include the selected sites, Read Later items, and notes, with their text, URLs, tags, descriptions, other supported metadata, an index, and relative links. These exports are unencrypted and always exclude content marked private, including content in private folders, even when it is currently unlocked for display. Export previews, filenames, indexes, and counts exclude that content too.

Ordinary JSON/ZIP backup files are unencrypted. Complete backups can include content marked private or currently hidden; keep them secure. Starting with 0.5.0, complete backups can also be exported as encrypted .covelet files with a separate password. Login credentials, sync connections, and passwords are excluded from complete backups. The backup password is not saved; losing it prevents recovery of the encrypted file. Encryption, decryption, and validation run locally. Restoration validates the file, asks for confirmation, and keeps a pre-restore copy in the browser.

Note history in 0.7.0 stores bounded pre-edit snapshots, up to twenty versions, and keeps the current version before an older one is restored. History follows note sync and the new complete backup format; the new reader still accepts old 0.6.0 backups. Encrypted complete backups include hidden content and note history within their scope by default, while excluding access credentials, hiding passwords, device keys and language preferences. Article/highlight caches, reading styles, RSS and local sessions are outside existing complete backups. Public reading items can be exported separately as unencrypted Markdown; marked private content remains excluded.

Browsers supporting writable selected directories can schedule daily or weekly encrypted backups and manage the latest three owned .covelet files. Setup saves a non-extractable encryption key, salt and directory handle in a dedicated local IndexedDB, without the original backup password. These capabilities are excluded from sync and backups. Disabling the schedule removes the local key and handle while preserving existing files. Background tasks never open a picker or request access. Lost directory permission stops the operation with a reauthorization message. Execution while the browser is closed or the system sleeps is not guaranteed. Firefox currently lacks this external-directory capability; manual encrypted export and recovery remain available.

You can edit or delete content, turn off sync, change backgrounds, revoke site permissions, and export backups. Feedback is voluntary. Covelet does not automatically attach logs, URLs, images, or backups.

The extension and the website

Covelet requires no account. The extension includes no ads, usage analytics, automatic log upload, or Covelet data server. Covelet does not sell data or use it for advertising profiles or credit decisions. Data use is limited to the features described above and follows the Chrome Web Store User Data Policy, including Limited Use.

Cloudflare Pages hosts this website. The homepage uses Cloudflare Web Analytics to measure website visits.
